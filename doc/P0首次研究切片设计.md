## 1. 这一步做什么

框架和 SQLite 已测通。下一步不做五个 Agent 齐开，只打通一条可运行的纵向切片：

```text
用户输入股票代码
  → 拉财务快照（代码计算，不交给模型算）
  → 基本面 Agent（抽取 → 规则 → 判断）
  → 简化综合决策（仅基于基本面）
  → SQLite 写入 run / report / decision
  → 终端输出结构化报告
```

验收标准：本机一条命令能分析一只股票，结果可复查、可重放、缺数据能弃权。

---

## 2. 非目标（本切片不做）

- 技术面 / 情绪 / 宏观 Agent
- 追踪 Agent、小时/天/周心跳
- 真实方法论库审核流（可用本地 fixture 规则）
- Streamlit
- 自动买卖、券商接口
- 把涨跌当对错标签

## 3. 冻结合同

`schema_version` 一律 `"1"`。业务 JSON 进 SQLite 后不原地改字段；升级走新版本。

### 3.1 EvidenceRef

```python
class EvidenceRef:
    ref_id: str
    kind: "field" | "computed" | "rule" | "kb" | "event" | "artifact"
    id: str                 # 字段名 / rule_id / kb_id / artifact://...
    observed_at: datetime
    source: str
    note: str | None
```

没有 EvidenceRef 的定量主张一律非法。

### 3.2 Snapshot（只读数据）

代码拉取并预计算后写入 Artifact，Agent 只读引用。

```python
class FundamentalSnapshot:
    schema_version: str = "1"
    stock_code: str
    company_name: str | None
    as_of: datetime
    price: float | None
    pe: float | None
    pb: float | None
    pe_percentile_5y: float | None
    pb_percentile_5y: float | None
    roe: float | None
    roe_stable: bool | None
    revenue_yoy: float | None
    profit_yoy: float | None
    gross_margin: float | None
    debt_ratio: float | None
    current_ratio: float | None
    operating_cf: float | None
    net_profit: float | None
    goodwill: float | None
    non_recurring_profit_ratio: float | None
    missing_fields: list[str]
    computed_flags: list[str]   # 如 cashflow_lag
    rule_hits: list[{rule_id, hit, detail}]
    artifact_ref: str           # 完整原始表
```

模型不做加减乘除。分位、同比、现金流 vs 净利润全部由代码写入 snapshot。

### 3.3 Report

```python
class Report:
    schema_version: str = "1"
    role: "fundamental" | "technical" | "sentiment" | "macro"
    score: int                  # 1–5
    stance: "buy" | "hold" | "sell" | "abstain"
    summary: str
    citations: list[EvidenceRef]
    risks: list[str]
    degraded: bool
    abstain: bool
    missing_information: list[str]
    # 基本面扩展；其他角色本切片不产出
    valuation: str | None
    financial_health: str | None
    earnings_quality: str | None
```

校验：

- `abstain=true` 时 `stance` 必须是 `abstain`
- `score` 在 1–5
- 非弃权时 `citations` 非空
- `summary` 中的财务数字必须能对上 snapshot 数值、`rule_hits` 阈值或 `score`（1–5）。年份（19xx/20xx）允许。证据绑定失败 → 本切片将 Run 标为 failed（单元测试）或纠正为 `abstain`（真实模型路径可配置）

### 3.4 Decision（本切片简化）

四维未齐时，决策不得假装有技术面/情绪/宏观。

```python
class Decision:
    schema_version: str = "1"
    rating: "buy" | "hold" | "sell" | "abstain"
    value_score: int | None     # 1–5；仅基本面时仍可给
    timing_score: int | None    # P0 必须为 None，明确「未评估时机」
    confidence: float           # 0–1；缺维必须打折
    rationale: str
    disagreements: list[str]    # P0 可空，但要写「仅基本面，其他维度未评估」
    falsifiers: list[str]       # 至少 1 条
    risks: list[str]            # 2–3 条
    advice_one_liner: str
    citations: list[EvidenceRef]
    dimensions_used: list[str]  # P0: ["fundamental"]
    dimensions_missing: list[str]
```

规则（代码，不靠模型自觉）：

- 只有基本面 → `confidence *= 0.6`，且不得高于 0.65
- 基本面 `abstain` → 决策必须 `abstain`
- 基本面失败 → 整次 Run `failed`，不编决策

### 3.5 InitialAnalysisRequest / RunRecord

```python
class InitialAnalysisRequest:
    run_id: str
    stock_code: str
    as_of: datetime
    output_schema_version: str = "1"

class RunRecord:
    run_id: str
    stock_code: str
    thesis_id: str
    mode: "research"
    status: "running" | "success" | "failed" | "degraded"
    snapshot_refs: dict         # {"fundamental": "artifact://..."}
    session_ids: dict           # {"fundamental": "..."}
    created_at: datetime
    updated_at: datetime
```

### 3.6 AnalysisDeliverable / ProcessRecord

运行时外壳，过程日志不进 `reports` 正文：

```python
class AnalysisDeliverable:
    task_id: str
    status: "completed" | "abstained" | "degraded"
    report: Report
    evidence_refs: list[EvidenceRef]
    missing_information: list[str]
    thesis_impact: "none" | "strengthen" | "weaken" | "invalidate" | "uncertain"
    facts: list[ExtractedFact]
    clues: list[Clue]
    judgment_basis: JudgmentBasis
    trace_steps: list[TraceStep]
    reflection: dict            # what_worked / what_was_missing / process_errors
    state_patch: StatePatch
```

字段定义见主设计文档 §6.3。P0 基本面也必须交 facts / judgment_basis / trace_steps；没有新闻时 `clues` 可为 `[]`。

Runtime 顶层仍是 `AgentFinalResponse`。`output` 至少含 `report` 与过程块；`reflection` 单独字段。编排把过程块打成 `ProcessRecord` 写入 artifact，并发 `process_logged`。`state_patch.base_version` 必须等于当前 AgentState.version。

## 4. 基本面 Agent

### 4.1 固定 System Prompt（应用层写死）

职责：价值/财务质量/安全边际。禁止评管理层诚信（无数据则 `insufficient_data`）。禁止预测股价。必须先列事实再判断。

### 4.2 资源白名单

| 资源 | 类型 | 作用 |
|------|------|------|
| `get_fundamental_snapshot` | Function | 读本次 Run 已算好的 snapshot |
| `search_methodology` | KnowledgeBase | 只检索 `approved` 且 scope 含 fundamental |
| `get_artifact` | Function | 按需展开 L0 外置原文 |

禁止：调度其他 Agent、写方法论正式库、拉行情做技术分析。

### 4.3 内部工作（不固定步数）

建议顺序，Agent 可自主补查：

1. 取 snapshot，列出 `missing_fields` 和 `computed_flags`
2. 按异常检索方法论（例如利润增、现金流不增 → 盈利质量规则）
3. 输出 Report

停止条件：关键主张已有证据，或明确弃权。

### 4.4 规则（代码先跑，模型只解释）

P0 内置一小套 fixture 规则，金融侧以后替换：

| rule_id | 条件 | 含义 |
|---------|------|------|
| `roe_quality` | ROE ≥ 15% 且负债率 < 60% | 盈利能力偏强 |
| `cashflow_lag` | `profit_yoy > 0` 且经营现金流 ≤ 0（P0 无现金流同比则用水平值） | 盈利质量存疑 |
| `high_leverage` | 资产负债率 ≥ 70% | 财务风险 |
| `valuation_rich` | PE 五年分位 ≥ 80% | 估值偏贵 |
| `valuation_cheap` | PE 五年分位 ≤ 30% 且 PE 有效 | 估值偏低 |

规则结果写入 snapshot.`computed_flags` 或单独 `rule_hits[]`，随 snapshot 交给 Agent。

## 5. 首次研究 workflow

应用层固定拓扑，不是全局 Agent 调度器：

```text
validate stock_code
→ create Run (status=running)
→ ingest_fundamental_snapshot（超时/重试走现有 RetryPolicy）
→ 数据严重缺失 → Run failed 或 degraded+决策弃权
→ FundamentalAgent.run(固定 InitialAnalysisRequest)
→ 校验 Report schema + 证据绑定
→ 简化 Decision（代码打折 + 一次 LLM 写 rationale/falsifiers，或纯模板）
→ 写入 reports / decisions / 更新 runs
→ 打印摘要
```

P0 决策优先 **模板 + 规则**，不必再开一个「决策 Agent」。缺维、弃权、置信度打折全部代码执行；LLM 只可选润色 `rationale`，且必须引用已有 citations。为降低失败面，第一版允许决策完全由模板生成。

## 7. 持久化用法（已有表）

| 表 | 写入 |
|----|------|
| `runs` | RunRecord；`snapshot_refs` + 建议 `process_refs` |
| `reports` | 基本面 Report JSON（结论，不含 facts/clues） |
| `decisions` | Decision JSON（拍板依据写满 rationale/citations/falsifiers） |
| `sessions` / `agent_states` | 基本面 Agent 会话 |
| `artifacts` | 原始财务表 + **ProcessRecord 全文** |
| `context_messages` | 工具调用链（无 reasoning_content） |
| `audit_events` | run_started / snapshot_ready / agent_completed / **process_logged** / decision_written / run_failed |

不把 snapshot 大表塞进 reports；reports 只引用 `artifact_ref` 和字段级 EvidenceRef。过程性日志走 artifact + `process_logged`，合同见主设计 §6.3 与 SQLite 设计 §6.8。

## 9. 测试必须过

1. fixture 股票：产出合法 Report + Decision，写入 SQLite，再打开库能读回  
2. 缺关键财务字段：`abstain`，决策也是 `abstain`  
3. 现金流落后净利润：`computed_flags` 含 `cashflow_lag`，报告 citations 含对应 rule

5. `timing_score` 恒为 null，`dimensions_missing` 含 technical/sentiment/macro  
6. `confidence` ≤ 0.65  
7. 原有 18 个运行时/持久化测试回归  
8. `--fixture` 路径零网络  

真实 DeepSeek 作为本切片必测项（fixture 数据 + 真实模型，不把 Key 写入仓库）。AKShare 仍为可选手动测，不作为 CI 必过项。

## 11. 自审

- **切得够窄**：一条命令、一个专家、一次落盘，能证明业务合同而不是再搭框架。  
- **诚实降级**：缺三维就写明未评估，而不是四个空 Prompt 凑热闹。  
- **数字在代码侧**：避免模型编 PE/ROE。  
- **测试可离线**：CI 不依赖 AKShare。  
- **风险**：AKShare 字段名变动 → 适配层隔离；模型仍可能在 summary 里写无出处数字 → 必须做数字抽取校验（简单正则/字段对照即可）。  

实现开始前以本文合同为准；与总设计冲突时，P0 以「能跑通、能弃权、能落盘」优先，四专家并行放到下一切片。

## 12. 实现前审核纪要

对照当前代码后的必要修正（已写入上文）：

1. **Runtime 合同**：Agent 只能返回 `AgentFinalResponse`。业务 `Report` 不能顶替它，必须放在 `output.report`。
2. **`timing_score: None` 不是合法类型**：改为 `Optional[int]`，P0 校验强制为 null。
3. **旗标命名**：统一 `cashflow_lag`，不再混用 `cashflow_lagging_profit`。
4. **证据绑定**：全文数字一刀切会误伤评分/年份；改为核对财务数字集合。
5. **真实 API**：本切片验证 DeepSeek Function Calling + JSON；财务数据用 fixture，避免 AKShare 把模型测试和数据测试绑死。
6. **SQLite**：`runs/reports/decisions` 表已有，缺的是 Python 写入 API，实现时补 `ResearchStore`。
7. **决策**：P0 用模板+规则生成，不把综合决策再做成 Agent，避免又一层 schema 失败。
8. **密钥**：只走进程环境变量，不写 `.env`、源码或测试文件。
