## 1. 结论

用户输入一段 prompt，**可选**带程序识别的 tag。编排（首次是 workflow，跟踪是追踪 Agent）先用代码解析 tag，再用 LLM 抽 `UserIntent`（每一维都有字段，抽不出就填 `"none"`，允许全 `"none"`）。非 `"none"` 的维写进该专家的 **Task Prompt**；System 与 Evidence **不出现用户内容**。需要记住的规则进 `UserPreference`。不存用户原话。

```text
用户输入 ──程序剥 tag──► tags[] / effect / body
         ──LLM 抽各维──► UserIntent（维字段 = 短任务句 或 "none"）
         ──tag 覆盖──► 被点名的维若仍是 "none"，程序写入 body 的抽取句
         ──分流──► this_run 注入 Task；remember 写偏好；rerun 重跑该维
```

## 3. 事后涨跌：两层不要混

后来的价**可以进复盘**，但不能当当时那份报告的证据，也不能当自动改策略的监督信号。

拆开：

**A. 当时记录真不真（T0）**  
`Report` / `ProcessRecord` 的 facts、citations、trace 只对应当时 snapshot。后来跌了不能改 PE、不能给旧引用加减分。涨了也不能证明当时推理合格。

**B. 这种判断后来好不好（T1，结果层）**  
复盘页 / Case **应该看**后来发生了什么，尤其是对照当初写的 `falsifiers`。一次没赚不等于思维链非法；完全不看涨跌则矫枉过正。

| 后来发生的 | 可以怎么用 | 不要怎么用 |
|------------|------------|------------|
| 打中当时 falsifier（如跌破当时写的 70 元） | 问 thesis 还在不在；**追加**跟踪/新 Decision；Case 记「证伪条件触发」 | UPDATE 旧 Report / 旧 Decision 正文 |
| 没打中条件，只是晃了一下 | 几乎不说明对错 | 「没赚就是链路错了」 |
| 同类口径反复亏，且当时字段就有却没引用 | 积 Case；过闸门再晋升检查项 | 单笔亏了就写 UserPreference、改权重 |
| 赚了 | 同样只是结果事实 | 拿收益给当时 citations 背书 |

**禁止（自动监督信号）：** 用随后盈亏回写旧结论、自动写偏好、不经闸门晋升方法论、用几天收益给系统打分调权。

**允许：** 当次行情进分析；跟踪用**新价**对照**旧 falsifier**；复盘同时展示「当时结论 / 后来价格 / 是否打中条件 / 当时有没有漏当时已有的字段」。

评测自动化仍看过程（弃权、句证、缺维），不以随后几天涨跌为通过标准。人审 Case 可以看结果层。

## 4. 谁拆 intent、分发给谁

首次研究：**Python workflow** 调一次抽取（快模型，可关 thinking）。不是主 Agent，也不让四个专家自己拆用户话。

```text
analyze_stock
  → 程序 parse_tags(用户输入)
  → LLM 填 UserIntent（六槽全填，可全 none）
  → 程序按 tag 修正槽位
  → 并行/串行跑专家：只把该维槽位 != "none" 的字符串写入该专家 AgentTaskPrompt
  → 决策环节只读 intent.decision != "none" 的字符串 + scope 含 decision 的偏好
```

- 槽位 `"none"`：该专家仍按固定职责做本维分析，Task 不加用户句。
- 槽位非 `"none"`：必须出现在该专家 Task 的 `required_questions` 或 `constraints`（见 §7），否则用户话对作业零作用。
- **不要**只把 UserIntent 存在编排内存里当「主 Agent 填过了」。

跟踪期同理：追踪 Agent 是调度方，抽取仍是编排函数，再写入被叫醒的那一维 Task。

## 5. Tag（取消卡片）

Tag **可选**。不选 tag 合法。  
Tag 由程序用固定词表从输入里识别并剥掉，**模型不许猜 tag，也不许改 tag 字段。**

词表（程序写死，大小写不敏感）：

| tag | 别名 | 程序写入 |
|-----|------|----------|
| `#fundamental` | `#基本面` | `tags` 含 `fundamental` |
| `#technical` | `#技术面` | `technical` |
| `#sentiment` | `#情绪` | `sentiment` |
| `#macro` | `#宏观` | `macro` |
| `#decision` | `#决策` `#global` | `decision` |
| `#tracking` | `#追踪` | `tracking` |
| `#remember` | `#记住` | `effect` 含记住 |
| `#rerun` | `#重跑` | `effect` 含重跑 |

未识别的 `#xxx` 忽略，不报失败。  
无维度 tag：`tags` 填 `["none"]`。  
无效力 tag：`effect` 填 `"this_run"`。  
同时有 `#remember` 与 `#rerun`：`effect` 填 `"remember_rerun"`。

剥掉全部已识别 tag 后的剩余文本称为 `body`。`body` 为空则视为 `"none"`。**`body` 不落盘。** 只在当次进程里给抽取模型当输入。

### 5.1 tag 对应的内容填到哪

没有单独的「tag 提示词模板」。tag 只决定 **哪一个槽位被点名**。槽位里的句子来自 LLM 抽取；若点名维仍是 `"none"` 且 `body != "none"`，**程序**把抽取失败的那一维写成对 body 的压缩任务句（见 §8.2），不是把 body 原文存库。

| 槽位 | 注入到谁 | 填 Task 哪个字段 |
|------|----------|------------------|
| `fundamental` | 基本面 `AgentInstance` | 非 none 时：`constraints` 一条「用户口径：…」；若句子是问句形态则同时进 `required_questions` |
| `technical` | 技术面 | 同上 |
| `sentiment` | 情绪 | 同上 |
| `macro` | 宏观 | 同上 |
| `decision` | 系统 `build_*_decision` 口径包 | 不进四专家 Task；写入决策模板的 `rationale` 约束说明（代码拼接，不是 LLM System） |
| `tracking` | 追踪 Agent 的 Task | `constraints` / `required_questions` |
| `#remember` | 不进专家 System | 分流写 `UserPreference`，scope=该非 none 维 |
| `#rerun` | 不进专家 System | 分流重跑非 none 或被 tag 点名的分析维 |

`#decision` / `#global` **不渗进**四专家。要点专家必须打专家 tag，或让 LLM 从 body 把句填进该维槽（无 tag 时允许）。

## 6. 合同

禁止 `Optional`、禁止 `str | None`。空标量 = `"none"`。`extra=forbid`。

合法维槽取值：非空 string。约定保留字 `"none"` 表示本维无用户口径。

### 6.1 `UserUtterance` 与 `UserPreference`

**都不存用户原话。** 二者不是同一件事：

| | `UserUtterance` | `UserPreference` |
|--|-----------------|------------------|
| 是什么 | **一次发言事件**（这次用了哪些 tag、effect、对应哪次 run、抽出的 intent 引用） | **跨次有效的一条口径规则** |
| 粒度 | 一次输入一行 | 一个 trigger + 一句 statement |
| 有无原话 | 无 | 无 |
| 会不会全 none | 会（用户随便打了字但各维都 none：仍记一次事件，tags 可为 `["none"]`） | 该次不新增行 |
| 以后画像 | 行为：常打哪些 tag、常反馈哪一维、remember 频率 | 内容：长期关心现金流、不要只报 PE |

```python
class UserUtterance:
    schema_version: str = "1"
    utterance_id: str
    user_id: str                      # 第一期 "local"
    moment: str                       # pre_run | post_decision | post_track
    effect: str                       # this_run | remember | rerun | remember_rerun
    tags: str                         # JSON 数组序列化后的 string，无 tag 为 '["none"]'
    intent_id: str
    stock_code: str                   # 无则 "none"
    thesis_id: str                    # 无则 "none"
    run_id: str                       # 无则 "none"
    created_at: str                   # ISO 时间
```

`tags` 用 string 存 JSON 数组，避免 schema 出现缺省字段。读出后程序解析。不允许 null。

```python
class UserPreference:
    schema_version: str = "1"
    preference_id: str
    user_id: str
    status: str                       # active | retired
    current_version: str              # 数字也写成十进制字符串，避免可选 int
    kind: str                         # preference | constraint | anti_pattern
    scope: str                        # 单 scope 名，或 "none"
    stock_code: str                   # 无则 "none"
    trigger: str
    title: str
    statement: str
    source: str                       # user_feedback
    source_utterance_id: str
    source_run_id: str
    created_at: str
    updated_at: str
```

一条 utterance 可派生 0～N 条 preference（每个非 none 维最多一条 statement）。  
`current_version` 用字符串 `"1"`、`"2"`，不做 Optional[int]。

冲突：同一 `user_id + scope + trigger` 下新条 retire 旧 active。

与方法论仍分开：偏好立刻 active；纪律走 candidate → 人工 approved。

### 6.2 `UserIntent`

抽取输出。六维槽 + 效力/id，**全部必填 string**。

```python
class UserIntent:
    schema_version: str = "1"
    intent_id: str
    utterance_id: str
    effect: str                       # 程序填，模型不许填
    tags: str                         # 程序填，模型不许填
    fundamental: str                  # 任务句或 "none"
    technical: str
    sentiment: str
    macro: str
    decision: str
    tracking: str
    not_evidence: str                 # 用户主张的非证据摘要，无则 "none"
```

模型只填六个维槽和 `not_evidence`。`effect`/`tags`/`intent_id`/`utterance_id`/`schema_version` 由程序写入后交给校验。

允许：六个维槽全是 `"none"`。含义是本次没有可分发的用户口径，专家走默认职责。

**不算失败：** 空 body、全 none、无 tag、只有无关闲聊被抽成全 none。

**才算失败（走现有通用错误，不造 intent 专用失败态）：** JSON 非法、缺字段、多余字段、`effect`/`tags` 被模型改写、维槽空字符串、维槽出现 null、类型不是 string。失败则当次不写入 preference、不分发用户句；专家若已在首次研究中，仍用默认 Task 跑完（与今天 P0 无用户句相同）。抽取失败要记 audit `intent_schema_invalid`，payload 不含用户原文。

`not_evidence`：用户提到的价/PE 等，一句摘要或 `"none"`。该字段 **不注入** 任何 Agent；只供编排丢弃，避免以后误写进 facts。

## 7. Prompt 三层与 Task 权重

```text
System    固定角色、工具、证据纪律、输出 schema
          禁止出现用户句、tag、preference 原文
Task      唯一允许出现用户口径的地方（已抽取的短句 / 已存 statement）
Evidence  snapshot、历史 report、规则命中
          禁止用户句、禁止 utterance 引用
```

System 只保留与用户无关的死规则，例如：「Task 中的口径只约束关注点与表述，不能替代工具数据。」这不是用户内容。

**权重（当次拼给专家的上下文，按字符预算，程序截断）：**

| 块 | 预算 | 说明 |
|----|------|------|
| System | 高、固定 | 不挤 |
| Evidence / 工具结果 | 约 50% | snapshot 与 artifact 摘要为主 |
| Task（职责 + 用户口径 + 本维偏好） | 约 30% | 用户相关合计硬顶：单维槽 200 字；本维 active 偏好最多 8 条、每条 80 字 |
| State 压缩 | 约 20% | memory_summary 等 |

超顶截断偏好（旧的截），audit `preference_truncated`。不截 System。用户口径进 Task 时字段优先：`required_questions` 高于 `constraints`；二者都来自同一维槽时，问号句进 questions，其余进 constraints。

## 8. 解析步骤

```text
1. 程序 parse_tags → tags, effect, body（body 仅内存）
2. 建 UserUtterance（无原话）+ UserIntent 壳（程序填 id/effect/tags）
3. body 为 "none"：六维槽直接 "none"，不调 LLM
4. 否则 LLM JSON：只输出六维 + not_evidence，值必须是 string
5. 程序合并：
     对每个被 tag 点名的维：若槽为 "none" 且 body 非 "none"，
     程序把该槽写成一句任务句（可再调一次「压缩成一句、禁止复述原文」；
     压缩仍失败则该槽保持 "none"，不把 body 原文写入任何表或 Task）
     未被点名的维：保留 LLM 值（含 "none"）
6. Pydantic 校验；非法 → intent_schema_invalid，六维视为全 none 继续默认分析
7. §9 分流
```

LLM 抽取 System（与专家 System 分离）：只抽取、不回答、不改评级、没有的维填字符串 none、不要输出 null、不要缺键。

## 9. 分流（原 6.2）

先看 `effect`，再看各维槽是否 `"none"`。

### 9.1 `this_run`（默认；首次分析常见）

对每个分析维 `v in {fundamental, technical, sentiment, macro}`：

- `v == "none"`：该维按固定 Initial 职责跑，Task 不加用户句。
- `v != "none"`：该维 Task 写入该字符串（questions/constraints 规则见 §7）。

`decision != "none"`：传给决策模板口径，不进专家。  
`tracking != "none"`：首次研究忽略（无追踪 Agent）；跟踪 workflow 才用。

不写 `UserPreference`。不改已落盘报告。  
全 none：等于今天的无用户句 P0，合法。

看完结果后再发 `this_run`：**不能改已落盘结论**。视为对新输入走一次分流；若要改结论必须带 `#rerun`。无 `#rerun` 的事后 this_run 只在「下一轮尚未开跑」时并入下一轮 Task；当前已结束的 run 不受影响。

### 9.2 `remember`

每个非 `"none"` 的维槽生成一条 `UserPreference`（scope=该维名，`statement`=该槽字符串，`trigger` 由程序从 statement 截前若干词，不做模型猜 tag）。  
`decision` / `tracking` 非 none 同样各写一条。  
全 none：不写 preference，utterance 仍记事件。  
不重跑、不改历史报告。下次开跑检索 active 偏好注入 **对应维 Task**（§7 预算）。

### 9.3 `rerun`

对「槽位非 none **或** 被维度 tag 点名」的分析维：再 `AgentInstance.run`，Task 带上该维槽（none 则只带已有偏好）。新 Report 新行。默认追加新 Decision，不覆盖旧行。  
未跑过的维：rerun = 该维第一次跑。  
只点 `#decision` 且四专家槽全 none：只重跑决策模板，不重跑专家。  
`#rerun` 但六槽全 none 且 tags 为 `["none"]`：不调度，当本次无操作（不失败）。

### 9.4 `remember_rerun`

先 9.2 再 9.3。

## 11. 用户画像

原料：`UserPreference`（长期口径）+ `UserUtterance`（行为事件：tag 分布、effect 分布、哪些维非 none）。  
仍无原话。底层读时聚合保留为模型证据，不再直接把效力/点名/槽位计数当成用户画像展示。

看板通过 `POST /api/v1/profile/generate` 调用模型，将以下结构化证据生成可读的投资者画像：

- 已记住的研究口径；
- 选股纪律与个股入池理由；
- 模拟持仓的仓位分布；
- 研究、记住和追踪行为的聚合特征。

输出包含投资者类型标题、总体描述、偏好的选股策略、决策方式、风险倾向、优势、可能盲点、自然语言证据依据和可信度。不得推断年龄、性别、职业、财富等敏感身份；专家私有记忆不作为用户偏好的证据。

模型结果追加写入 `user_profile_snapshots`，看板默认展示最近一版并允许重新生成。明确表达过的口径和选股记忆保留在画像下方作为可管理依据，而不是画像主体。

## 13. 分期

| 期 | 做什么 |
