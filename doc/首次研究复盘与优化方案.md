## 1. 现在系统实际在干什么

用户丢一个 6 位代码进来，首次研究是：

1. 拉一次数据切片（财务、行情、事件、利率）
2. **四个分析 Agent 并行**，互不通信：基本面、技术面、情绪、宏观
3. **系统环节**做校验、综合决策、落盘（决策不是第六个 Agent）
4. 打印报告。免责：研究辅助，非投资建议

四个专家各自只读自己的工具。宏观**不投票买卖**。`rating` 只由基本面 / 技术 / 情绪投票。

追踪 Agent 按设计是「对照上次 thesis 和增量，决定叫不叫、叫谁复评」。代码里首次 workflow **没有** `_run_tracking_agent`。用户 prompt 里的 `#tracking` 槽可以存意图，但首次不会叫醒追踪角色。

## 2. 四个 Agent 干活怎么样（实盘观感）

近期实盘（无 fixture）看过：平安银行 `000001`、美的 `000333`、中国平安 `601318`、五粮液 `000858`。

总评：**能交卷、不串台、合同大体守住**；当作分析师看，还是「会读快照的实习生」——数字对得上，方向偏保守。

| Agent | 重量 | 实盘印象 | 典型工具路径 |
|------|------|----------|----------------|
| 基本面 | 重 | 最好用，主结论靠它 | snapshot → 偶尔 `get_artifact` / methodology → `submit_final` |
| 技术面 | 重 | 最稳，很少崩，几乎永远 hold | 指标 + K 线 + 价格 → methodology → 一次交卷 |
| 情绪 | 中 | 有回购/减持就有料；事件太旧就弃权 | `get_event_snapshot` + `get_holder_changes` |
| 宏观 | 轻 | 改策略后会自己判相关；仍不投票 | 只碰 `get_macro_snapshot` |

隔离是真的：没有互相调错工具。情绪 citation 已是 `event:` / `event:{code}:holder:`。宏观改完后：平安（保险+银行）判 high，五粮液判 low，银行判 high。

决策几乎总是 **hold**，置信度大约 0.4–0.7。四个人能同时交卷，但投票端很保守：技术不给方向，宏观不投票，情绪要么弃权要么和基本面拧着，多数票拉回 hold。

## 3. 问题清单与解决方案

### 问题 A：宏观以前「老弃权」

**现象**  
白酒、家电几乎必弃权；连中国平安也曾弃权。看起来像宏观没干活。

**原因（不是模型胆小）**  
旧策略用行业字符串**词表命中**：只认「银行 / 地产 / 房地产 / 保险 / 证券 / 信托」。东财 `industry` 经常是一句经营描述，不是标准行业名。例如中国平安是「提供多元化的金融产品及服务」，句子里没有「保险」，规则打成 `low_relevance`，编排**强制弃权**。A 股大多数票都不在这六个词里，所以你会觉得「老弃权」。

这其实有一半是产品故意的：宏观只做利率环境标签，不许给五粮液编「所以该买」。另一半是词表误伤了综合金融。

**已做（待你确认保留）**  
- 去掉词表对弃权的强制。  
- 快照仍给公司名、行业原文、LPR。规则只打 `lpr_missing`。  
- 专家根据「利率会不会一阶影响这家公司的盈利/资产负债表」自己填 `high / low / unknown`。  
- 编排只收口：`low` → 弃权且不投票、算已评估；`high` → `hold`；漏填或 `unknown` → 算缺维。仍然禁止宏观 `buy`/`sell`。

**验收**  
实盘：`601318` 应为 high（保险+银行业务），`000858` 可为 low，`000001` 应为 high。不要因为 industry 句里没有「保险」就弃权。

**不改回去的理由**  
词表省钱、可复现，但和东财字段形态打架。模型会误判，但误判可以在报告里看见；词表误杀是静默的。

---

### 问题 B：宏观「看起来总齐全」和「老弃权」是两件事

**现象**  
改语义之后，`dimensions_used` 经常四维都在，`missing=[]`。有人会以为宏观分析做得很满；有人会问为什么还弃权。

**原因**  
决策层把 `relevance=low` 的弃权当成 **「本维已经回答了：这题不该宏观答」**，不算缺维，也不因此 `degraded`。齐全 = 流程交了卷，不是宏观研究很深。弃权 = 产品规定低相关不投票，或专家判断低相关。

**建议**  
看板/CLI 不要只显示 used/missing。宏观一行固定写成：

- `宏观：相关 high，环境标签 hold`  
- 或 `宏观：相关 low，本维不形成方向（已评估）`  
- 或 `宏观：unknown / 无 LPR，缺维`

**验收**  
五粮液：used 含 macro，rationale 含「本维不形成方向」，run 不因宏观 degraded。

---

### 问题 C：证伪条件是空话，跟踪期无法打勾

**现象**  
四维跑完后，决策里的 falsifiers 经常是一句：「若后续新增信息与当前判断方向相反，则本次判断失效」。代码就在 `decision.py` 的 `_merge_falsifiers`：报告 schema 不带 falsifiers，决策侧写死这一句。

**为什么要紧**  
第五个 Agent 以后要对照 thesis 决定 `unchanged / review / invalidate`。对照空话，只能天天 review 或永远 unchanged。

**解决方案**  
- 每个分析 Agent 交卷带 1–3 条**可验证**证伪（字段、价位、事件 id、日期）。  
- 决策合并去重，最多保留 3 条，禁止套话过门。  
- 示例：  
  - 基本面：经营现金流连续两期无法覆盖净利润  
  - 技术：收盘跌破本次给出的 MA60 / 明确支撑位  
  - 情绪：窗口内出现控股股东减持公告  
  - 宏观（仅 high 时）：LPR 方向与当前环境标签假设相反  

**验收**  
任意成功 run 的 falsifiers 里，至少有一条能让人拿公开数据打勾/打叉，不能只有「信息相反则失效」。

---

### 问题 D：情绪过期事件要么瞎写、要么拖垮整轮

**现象**  
美的有回购、五粮液有公告时，情绪能写出有用的 buy，和基本面 hold 形成分歧——这是四维里最有信息量的一次。  
平安银行只有多年前高管增持，专家弃权，整轮 `degraded`，置信度被打到约 0.42。弃权本身比编「情绪中性」强；但「没近窗事件」不该等于「研究失败」。

**原因**  
没有统一的事件时效窗口。旧 holder 变动仍在快照里，模型要么当新闻、要么整维弃权。决策把情绪弃权当缺维，run 变 degraded。

**解决方案**  
- 切片里带 `as_of` 与每条事件的日差。  
- 超过窗口（建议默认 90 天，可配置）的变动降为线索，**不得支撑非弃权 stance**。  
- 窗口内无有效事件：本维弃权，`missing_information` 写清「无窗口内事件」。  
- 决策：这种 N/A **不算整轮 degraded**（对齐宏观 low 的「已评估」），置信度仍可因缺投票维略降，但不要和「Agent 崩了」混为一谈。

**验收**  
`000001` 若近窗无事件：情绪可弃权，run 不因此 degraded；`000333` 有回购进展时仍可非弃权。citation 继续用 `event:`，不要重复同一个 id。

---

### 问题 E：技术面太稳，几乎永远 hold，没有跟踪锚

**现象**  
工具路径干净（三件套必调），很少交卷失败。stance 几乎锁死 hold。citation 有时把 `ma5/ma10/ma20` 糊成一个 id；知识库会套 `kb_rsi_overbought` 哪怕 RSI 并不超买。

**原因**  
Prompt 偏「别说错」。指标预计算是对的，但没有强制「关键位必须是本次 K 线里的数字」。跟踪期「跌破关键位 → 叫醒技术」需要锚，现在没有。

**解决方案**  
- Prompt：趋势完整且未跌破关键位时允许非 hold；禁止无依据的 buy/sell。  
- `key_levels` 必须带数字（支撑/阻力来自本次 K 线或均线）。  
- citation `id` 只能是单一字段名。  
- 知识库条目必须和指标对得上，对不上不许引用。

**验收**  
报告里能找到至少一个可核对价位。连续多只股票不全是 hold（允许多数 hold，不允许 100% hold）。

---

### 问题 F：基本面最有用，但交卷脏、爱搜 methodology

**现象**  
会打 `cashflow_lag` / `high_leverage` / 估值分位，银行高负债能当行业特征解释。弱项：`submit_final` 偶发 Invalid JSON，失败回传后重交通常成功（平安银行实盘连失败两次才过）。报告里会冒出不该有的 `relevance_to_stock`，还会抱怨「快照没有利率」（那是宏观的活）。有的 run 连搜三次 methodology。

**解决方案**  
- 失败回传带 schema 摘录 / 「不要重复字段」提示，降低 JSON 重试。  
- 按 `role` 丢掉别人的字段再落盘。  
- Prompt：snapshot 够用就交卷；methodology 命中规则再搜，默认 0–1 次。  
- 高负债：银行/保险必须引用 `high_leverage`，同时允许用行业口径解释，不许假装没看见。

**验收**  
同代码连跑几次，基本面 `submit_final` 首次成功率明显好于「经常第二次才过」。落盘的基本面报告没有 `relevance_to_stock` / `cycle_tag`。

---

### 问题 G：决策永远综合 hold，分歧被吃掉

**现象**  
美的、五粮液出现过「基本面 hold、情绪 buy」，决策仍是 hold。用户看到的是一张太平报告。

**原因**  
三票（基本面/技术/情绪）多数表决，宏观不投票。技术常 hold，情绪一弃权就只剩两票，很容易 hold。advice 写成「价值面 x/5，时机面 y/5，综合 hold」，不展示张力。

**解决方案**  
- 表决规则先不动（避免宏观重新主导买卖）。  
- advice / rationale 必须带上未吸收的分歧（例如「情绪偏多，基本面未确认」）。  
- 置信度照旧因分歧打折。

**验收**  
存在 stance 冲突时，CLI 文本里能看到冲突双方，而不是只有综合 hold。

---

### 问题 H：共用 Report 字段串台

**现象**  
同一套 Report schema 给四维用。技术报告上出现 `relevance_to_stock`，基本面缺利率，宏观 citation 出现 `company_name` 这种非利率字段。

**原因**  
`extra=forbid` 但仍是一张大表，模型爱填满。编排没有按 role 洗字段。

**解决方案**  
落盘前按 role 白名单保留字段。citation `kind`/`id`/`source` 必须能对上该维快照。

**验收**  
单测：给基本面塞 `cycle_tag`，落盘后为空；给宏观塞 `valuation`，落盘后为空。

## 4. 第五个 Agent：干什么、什么时候干

追踪 Agent **主要在跟踪期发挥作用。首次 workflow 里它不干活。** 这是设计原意，不是漏做。

| | 首次研究 | 跟踪期 |
|--|----------|--------|
| 谁干活 | 四个分析 Agent + 系统决策 | 追踪 Agent 调度，分析 Agent 按需被叫醒 |
| 问题 | 这只股票现在怎么看 | 相对上次 thesis，要不要重评、评哪一维 |
| 输出 | Report ×4 + Decision | `unchanged` / `review` / `invalidate` |
| 禁止 | 专家互相聊天、宏观主导买卖 | 追踪代写专业结论、无差别四连重跑 |

追踪读取：上次决策、`falsifiers`、增量（价、公告、holder）、四维状态摘要。事件路由（财报→基本面，破位→技术，减持回购→情绪，利率政策→宏观且仅相关时）。能不叫专家就不叫；默认 0 个，最多 1 个（v0 建议）。冷却和去重比把 Prompt 写长更重要。

**为什么现在不上**  
基线证伪还是空话，情绪时效未定，技术没有价位锚。上了只会空转。

- 技术关键位数字、允许非 hold

### 第 3 步：追踪 v0（单独命令）

例如 `python -m insightagent track <thesis_id>`。首次研究仍不调用它。

不做：方法论库治理、小时级无差别巡检、追踪改专家 system prompt / 工具 / schema。

## 7. 和设计文档的关系

- 4 分析 + 1 追踪、宏观为轻、决策是系统环节：仍有效。  
- 宏观「不相关则弃权、不主导买卖」：仍有效；**改的是「谁来判相关」**（模型，不是词表）。  
- 追踪「事件路由、少调用」：仍有效；本文只是把前置条件写清楚。  
- 任务书里「弃权进 missing / 词表命中」：与现状和本方案不一致，审核通过后再改任务书。
