# 知识库：书目找全了之后怎么处理

> 状态：**待你审，未实现**  
> 日期：2026-08-27  
> 位置：本仓库 `doc/`  
> 关联：`知识库做法-Wiki与短条目.md`、`知识库-PDF转Markdown.md`、四份 `知识库资料-*.md`  
> 前提：经管已把书目/全文找齐。**经管不再写卡片。** 蒸卡与跟踪调度是 **同一个追踪 Agent**（同一角色、同一套 System、不同 Task）；四个分析 Agent 运行时仍不读文献。  
> **不写第二个蒸馏专用 Agent。不写全书 RAG。不自动批准。股票小时/天/周心跳仍后做。**

---

## 0. 结论

经管的活到「把全文交到 incoming」为止。后面全是咱们：

```text
点收路径/文号（咱们，对照清单）
  → 本地 pdf2md（只转马上要蒸的短文/指定章，不发 PDF 上网）
  → 追踪 Agent（蒸馏 Task）：一次只读一章或数页 md + 允许的 flag 名表
       → 只准写 candidate 卡片（id / trigger / text / evidence_required）
  → 夹具：该引 / 不该引
  → 咱们 CLI 批准后，search_methodology 才可见
```

**四个分析 Agent 不读文献、不蒸卡。** 研究某只票时它们只对已批准卡片 `search_methodology`。

追踪 Agent = 知识库管理者 + 以后的跟踪调度。本期只实现它的 **蒸馏 Task**（工具：读白名单 md、查已有条目、提交 candidate）。**不**注册四个分析 AgentSkill，**不**跑持仓心跳。同一 `tracking.py` / 同一 System Prompt，跟踪期再加增量工具和 AgentSkill。

## 1. 分工（按你的决定改过）

| 经管 | 咱们 |
|---|---|
| 按清单找全文，交文件 | 点收、`pdf2md`、检索改库 |

经管交件验收：清单每条有文件、法规首页文号对。**不再要求他们交 YAML 卡片。**

## 2. 追踪 Agent 的蒸馏 Task（不是第四个分析角色，也不是新 Agent）

入口建议：

```text
python -m insightagent kb distill path/to/chapter.md --scope fundamental
```

内部就是 `tracking` 角色跑一轮：Task Prompt 写明「本轮只蒸馏、禁止调度专家、禁止改 approved」。

行为：

1. 只读 **白名单 md**（先本地 `pdf2md`）。不读 PDF，不上云 OCR。  
2. 一次一章或数页（硬顶建议 ≤ 8k 字）。禁止整本一次丢进去。  
3. 工具给出本角色允许的 flag 名；`evidence_required` 必须落在这张表上，否则卡片作废。  
4. 可 `search_methodology` 已有条，去重、标冲突，只 `submit_candidate`。  
5. `text` ≤ 200 字；禁止买卖指令、禁止大段抄原文。  
6. **不能**把 candidate 标成 approved（设计已冻结，跟踪期同样不能）。

模型仍用 DeepSeek。和全书 RAG 的差别：追踪 Agent 离线把一章收成卡片；`analyze` 只检索卡片。

跟踪心跳上线后：同一 Agent 换 Task（增量 + 可选叫醒专家），蒸馏工具可以仍留在它的注册表里，默认跟踪轮次不调用。

## 3. 文件与点收（咱们做，经管只交包）

```text
data/kb/incoming/     经管交来的原件，gitignore，禁止 commit，禁止把 PDF 发给 DeepSeek
data/kb/markdown/     pdf2md 产出；教材全书 md 不进 git
doc/kb-entries/       追踪 Agent 蒸馏写出的短卡片（可 git）
```

点收仍要做：法规对文号、缺正文打回、教材先备查只抽需要的章。点收未完成不要对整夹盲目 `distill`。

优先拿去转+蒸的仍是短官方文本（65 号、CAS 31、回购指引、LPR 公告正文、均线/RSI 定义那一节），不是先蒸教材全书。第一批主题仍见下文 §5。

---

## 4. 总流程

```text
经管全文
  → 咱们 pdf2md（P0 短文 / 指定章）
  → kb distill（追踪 Agent → candidate）
  → 测试：flag 真应命中、flag 假不得命中
  → kb approve（咱们）
  → analyze 里专家 search_methodology(query + flags)
```

禁止：切片进向量库当知识库；PDF/整本 md 发给 DeepSeek；飞书当 approved；`#remember` 写入方法论。

可选人工：md 页眉太乱时删一下再蒸。不是经管的任务，也不是每页必校。

## 5. 第一批（AI 按这个清单蒸，不超过约 20 张批准条）

对齐 **机器已经在算的 flags**。现有内存 id 迁进库并补 `evidence_required`，蒸馏时优先「改写/补全」这些 id，不要另起同义卡。

| 建议 id | 角色 | 必须能对上的机器条件 | 喂给蒸馏的原料 |
|---|---|---|---|
| `kb_cashflow_lag` | 基本面 | `cashflow_lag` | CAS 31 相关页 |
| `kb_value_trap` | 基本面 | `value_trap_risk` | 估值+盈利质量指定节 |
| `kb_roe_quality` | 基本面 | 长期 ROE 相关 flag | 对应节，不是整本 Penman |
| `kb_pe_percentile` | 基本面 | `pe_percentile_5y` | 估值指定节 |
| `kb_non_recurring` | 基本面 | 扣非相关字段 | 〔2023〕65 号 |
| `kb_ma_align_not_signal` | 技术面 | 四线排列 flag | 均线定义节 |
| `kb_rsi_overbought` / `oversold` | 技术面 | **仅** RSI 过线 | RSI 定义节 |
| `kb_buyback_event` | 情绪 | `has_buyback` 等 | 回购指引 |
| `kb_inquiry_event` | 情绪 | 问询/立案 flag | 问询指引 |
| `kb_macro_low_relevance` | 宏观 | 相关度低则弃权 | LPR 公告正文等 |

卡片字段仍须能回答：何时用、看哪个已有字段、例外、出处。模板与设计 §9 一致，`status` 默认 candidate。

## 6. 运行时检索（蒸完且批准之后）

与 `知识库做法-Wiki与短条目.md` §4 相同，不改成 Wiki：

1. 只 `approved` + 本角色 `scope`  
2. 空 query → `[]`  
3. `evidence_required` ∩ 本次 snapshot flags  
4. query 与 `trigger` 求交  
5. 最多 3 条进工具返回；报告引用必须在这次返回里  

专家生成 query、命中则放入上下文——这一句只描述 **analyze**，不描述蒸卡。

## 7. 分期

| 期 | 做什么 | 完成标志 |
|---|---|---|
| 点收 | incoming 对清单 | 每条有路径或未齐原因 |
| K0 | 空 query 不返回、scope、最多 3 条、未检索 kb 丢掉 | 未超买不误引 RSI 条 |
| K1 | 内存条迁 SQLite；`kb import/approve/show` | 运行时不再读数组 |
| K2 | 追踪 Agent 蒸馏 Task + §5 第一批 candidate，咱们批准 | 夹具该引/不该引；**无**小时心跳 |
| K3 | 其余法规按需 distill | CLI 能驳回 |
| 以后 | 教材某章按需蒸；追踪只写 candidate | 另开篇 |

K0 不依赖蒸馏。K2 才消耗经管全文。
