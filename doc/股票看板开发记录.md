# 股票看板开发记录

> 对应方案：`doc/轻量股票看板平台方案.md`
> 当前阶段：**B1 已完成**
> 最后更新：2026-08-25

## 目标与范围

B0 交付全市场 A 股延迟行情的本地看板：批量采集、SQLite 批次存储、查询 API、搜索分页页面、数据截至时间和过期提示。B0 不包含 K 线、公告、自选股或 Agent 联动。

## 已完成

- 建立独立 `src/insightboard/` 包，与 `insightagent` 的研究库和运行流程隔离。
- 设计 SQLite 批次表 `quote_batch`、行情表 `quote_snapshot`、当前批次指针 `board_meta` 和采集审计表 `ingest_run`。
- 写入新批次并校验后，才在同一事务更新当前批次指针；API 因而只会读取完整成功批次。
- 实现单次采集入口、状态查询和本机 FastAPI 看板页面。
- 实现工作日交易时段内每 30 分钟运行的独立 worker；同一任务不重入，worker 启动时尝试执行一次。
- 增加 5 个离线测试，覆盖批次发布、失败保留旧数据、审计、API 和过期状态。

## 数据源预研

- 本机安装并验证版本：AKShare `1.18.94`。
- 可发现全市场行情候选：`stock_zh_a_spot_em`、`stock_zh_a_spot`、`stock_zh_a_spot_tx`。
- 真实调用结果：2026-08-25，本机调用东方财富接口时被远端主动断开，报 `RemoteDisconnected` / `ConnectionError`，未能得到可用数据样本。
- 用户首次执行 `collect-once` 时复现同一错误；CLI 已改为简洁提示并返回退出码 1，不再直接显示长 traceback。详细失败信息仍写入 `ingest_run`，且不会覆盖上一批成功数据。
- 腾讯接口 `stock_zh_a_spot_tx` 实测成功：返回 5550 条，耗时约 15 秒，包含代码、名称、最新价、涨跌幅、成交量、成交额和市盈率字段。
- 新浪接口 `stock_zh_a_spot` 实测成功：返回 5549 条，耗时约 52 秒；Windows 环境存在字段名乱码，因此只作为腾讯失败后的备用来源。
- 当前默认源已改为腾讯，新浪作为自动备用；东方财富接口不再用于 B0 看板采集。

## 方案问题与最终处理

| 问题 | 最终处理 |
|---|---|
| 原方案没有固定可用的批量接口 | 将 AKShare 采集器隔离为 `QuoteCollector`，腾讯为默认来源、 新浪为备用；真实接口失败不会清空上一批数据。 |
| “staging 表原子切换”没有实现细节 | 使用不可变批次数据加 `current_quote_batch_id` 指针；在单一 SQLite 事务内发布指针。 |
| B0 同时引入 Vue 工程会增加未验证阶段的依赖 | B0 使用 FastAPI 静态页面完成最小验证闭环；Vue 迁移保留给前端功能扩展时处理。 |
| 原方案仅建议 90% 覆盖率 | 当前 B0 先校验非空、代码合法、代码唯一、价格非空比例至少 80%；等取得真实样本后再根据实际市场覆盖数量加入绝对覆盖率。 |

## B1 开发进度

- 已新增日 K、公告标题、自选股和深数据队列表；日 K 每股写入时截断为最近 250 条，公告标题截断为最近 30 条。
- 个股详情页只请求本地 API。缺少 K 线和公告时，它通过 `POST /stocks/{code}/refresh-request` 入队，不会由浏览器同步调用 AKShare。
- worker 每分钟最多领取一个深数据任务。日 K 获取失败会保留队列并记录错误；公告获取失败暂不阻断已成功取得的日 K。
- 已新增详情 K 线图、公告标题列表和本地 `local` 自选股页面。
- 自动采集 worker 的多周期实测仍待用户有时间时观察；此轮开发未将其宣称为长期稳定。
- 真实单股 K 线验证首次使用东方财富 `stock_zh_a_hist` 时被远端断开。已调整为腾讯 `stock_zh_a_hist_tx` 优先、东方财富备用；需继续实测腾讯单股 K 线接口。
- 腾讯单股 K 线接口实测成功：`000001` 返回最近 250 条日 K；同次公告标题采集返回 30 条。个股深数据不做全市场预抓取。

## B1 验收

- 离线测试覆盖队列领取、K 线与公告存储、自选增删、B1 API 入队与读取。
- 真实数据验证：腾讯日 K 获取成功；公告标题获取成功。
- 实际使用验证：打开个股详情后，K 线和公告会通过后台队列逐步采集并显示；由于队列每分钟最多处理一只股票，首次打开不会立即显示深数据，这是预期的低频限速行为。
- 后台 worker 仍建议在正常使用中持续运行观察。队列按分钟处理一只股票，满足按需、低频采集，不会因打开详情页立即从浏览器请求外部数据。
- 当前未完成连续多个交易日的长期稳定性测试；该项作为后续运行观察，不阻塞 B1 功能验收。

## 运行方式（开发中）

```powershell
python -m insightboard init
python -m insightboard collect-once
python -m insightboard worker
python -m insightboard serve
```

默认数据库为 `data/board.db`，API 与页面监听 `http://127.0.0.1:8000`。
