## 0. 结论

可以接，而且应该现在接。看板已经能看延迟行情、K 线、公告、自选；研究侧已经能从「股票代码 + 一句话」出四维报告，并能对着报告再说一句（记住 / 重跑某一维 / 结束）。缺的是同一张页面上的按钮和进度，而不是再发明一套研究引擎。

两套系统继续拆开：

| | 看板（已有） | 研究（已有） | 本期要做 |
|---|---|---|---|
| 干什么 | 全市场延迟行情 | 对 **一只已指定的票** 做四维分析 | 在个股页发起研究、看报告、再反馈 |
| 库 | `data/board.db` | `data/insightagent.db` | 只加一张 **作业表** 把两边串起来 |
| 出网 | 采集 worker 打行情源 | `analyze` / `feedback` 打 DeepSeek（财务等仍可走现有 Agent 适配） | HTTP **不**同步等 70 秒；后台跑现有 `analyze_stock` / `feedback_on_run` |

**半小时全市场重跑四维：明确不做。** 研究只发生在用户点了某只票、或自选里手动点「研究」。

原方案 B2 还有「Agent 读看板行情/K 线」。本期 **可以顺手做技术面读板**（有日 K 就用，没有再 fallback 现网）；财务/现金流仍用现有 Agent 取数。不要为了读板把研究卡住。

## 1. 用户在看板上怎么用（只接已有能力）

个股页（现有详情）增加研究区，列表页不刷研报。

```text
市场表 / 自选  →  点进 000858
  → 仍是：延迟行情、K 线、公告、加入自选
  → 新增：一句话输入框 +「开始研究」
  → 进度：排队 / 进行中 / 成功 / 失败（轮询，不要 WebSocket）
  → 成功：意图理解（非原话）+ 四维摘要 + 决策一句话
  → 同一页再输入一句 →「对本次结果反馈」（走现成 feedback_on_run）
```

和 CLI 对齐，不改语义：

| 页面动作 | 对应现有能力 |
|---|---|
| 开始研究 + 可空的一句话 | `analyze_stock(code, user_prompt=…)`；空则 `none` |
| 展示「意图理解」 | `format_intent_echo` 那套：效力 + 各维译文，**不回显用户原话**，**不必打印 `#rerun`** |
| 对最新成功报告再说一句 | `feedback_on_run(parent_run_id, user_prompt=…)` |
| 口语「再出一版基本面 / 记住 / 结束」 | 现有抽取 LLM：无 `#` 也能判 rerun / remember / end |
| 结束 | 不重跑、不改旧报告；页面提示「未改结论」 |

免责声明：研究区固定「研究辅助，非投资建议」。决策 rating 不是下单指令。

## 2. 为什么作业必须异步

一次真实 `analyze`（行情 + 四专家）大约一分钟级。FastAPI 请求里直接 `await analyze_stock` 会拖死页面、也容易超时。

做法与 B1 深数据队列同一思路：

```text
浏览器 POST /research/jobs
  → 只写入作业行（queued）+ 返回 job_id
研究 worker（独立进程，或 insightboard worker 里加一个低并发槽）
  → 领取 queued 作业
  → 调现有 analyze_stock / feedback_on_run
  → 把 run_id、status、error 写回作业行
浏览器 GET /research/jobs/{id} 每 2～3 秒，直到 success / failed
再 GET /research/runs/{run_id} 展示报告（从 insightagent.db 读）
```

约束：

- **全局同时只跑 1 个研究作业**（DeepSeek + 源站都经不起并发轰炸）。
- 同一 `stock_code` 已有 `queued`/`running` 则拒绝再排队，返回现有 `job_id`。
- 失败保留错误类型短句；**不把** DeepSeek 原文、用户原话写入看板库。
- 采集 worker 与研究 worker 可以同机两个进程，避免研究把 30 分钟行情节拍打乱。第一期若只开一个 worker，研究槽必须 `max_instances=1` 且不要和行情 job 抢死锁。

环境：`DEEPSEEK_API_KEY` 只给研究 worker，不给浏览器，不给纯行情采集（采集用不到）。

## 3. 库怎么串（不合并两个 db）

继续两个文件：

- `board.db`：行情、K 线、公告、自选、**研究作业索引**
- `insightagent.db`：snapshot、四份 Report、Decision、意图、偏好、artifact

看板作业表（建议名 `research_job`）只存索引，不复制研报正文：

| 字段 | 含义 |
|---|---|
| `job_id` | uuid |
| `user_id` | 先写死 `local` |
| `stock_code` | 六位 |
| `kind` | `analyze` / `feedback` |
| `parent_run_id` | 仅 feedback |
| `run_id` | 成功后填 Agent 的 run |
| `status` | `queued` / `running` / `success` / `failed` |
| `error` | 短错误，可空 |
| `created_at` / `updated_at` | UTC |

用户 prompt **不要**进这张表（与 Agent「不落原话」一致）。prompt 只在 worker 内存里传给 `analyze_stock` / `feedback_on_run`，由 Agent 侧抽槽后只存译文。

展示用的报告：API 用 `ResearchStore.get_run(run_id)` 读 `insightagent.db`，再收成看板 JSON（见 §4）。artifact 大文本仍只在 Agent 的 `data/artifacts`。

个股「当前研究」：该票最近一条 `success` 作业的 `run_id`。反馈默认针对这个 run（与 CLI `feedback <run_id>` 相同）。若用户点开历史，可列该票最近 N 次 job（N≤20），不做无限聊天记录。

## 4. API（加在现有 `/api/v1` 上）

现有 quotes/bars/notices/watchlist **不动**。新增：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/research/jobs` | body：`stock_code`，`prompt`（可 `""`/`none`），可选 `kind=analyze` |
| POST | `/research/jobs/{job_id}/feedback` | body：`prompt`（必填；`none` 则与 CLI 一样空操作、不建子 run） |
| GET | `/research/jobs/{job_id}` | 作业状态；成功时带 `run_id` |
| GET | `/research/stocks/{code}/current` | 该票最新成功 run 的摘要；没有则 404 |
| GET | `/research/runs/{run_id}` | 展示用：意图 echo 字段、四维 stance/score/summary、决策 rating/confidence/一句话、`parent_run_id`、`rerun_dimensions` |

`GET /research/runs/{id}` **禁止**返回用户原话、完整 citations 堆也可以先精简（第一期：四维 summary + 决策 + 意图效力/各维译文足够）。数字仍以 Agent 已绑定的为准，前端不重算。

错误：`409` 该票已有进行中作业；`400` 代码非法；`503` 未配置 `DEEPSEEK_API_KEY`（研究 worker 健康检查）。行情 API 缺 key 不得 503。

鉴权：仍仅 `127.0.0.1`。CORS 不扩大。

## 5. 页面改动（现有静态页即可，不必先上 Vue）

在 `index.html` 个股详情里加一块 `#research-view`：

1. textarea：placeholder「可说人话，例如：记住别只看便宜」  
2. 按钮「开始研究」→ `POST /research/jobs`  
3. 状态行：排队中 / 研究中 / 失败原因  
4. 成功卡片：意图理解；基本面/技术/情绪/宏观各一行 stance+摘要；决策一句话；免责  
5. 反馈 textarea +「对本次结果反馈」→ `POST .../feedback`  
6. 若返回未重跑（结束 / 只记住）：提示「旧报告未改」，不要空白当失败  

列表和自选 **不**加自动研究。顶栏新鲜度仍只表示行情批次，不要和研究作业混成一条「数据截至」。
