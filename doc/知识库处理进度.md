## 4. 本轮执行方案

本轮改用已验证可用的 DeepSeek，不再使用 Step Plan。执行时采用单线程、可恢复批处理，严格按以下顺序处理：

1. `fundamental`
2. `technical`
3. `sentiment`
4. `macro`

每个 scope 内逐个文件处理，不并发、不重复处理已经完成的文件。只处理转换状态为 `ok` 的 Markdown；`needs_ocr` 文件本轮跳过，不补做 OCR。

### 文件筛选规则

- Markdown 不超过 80,000 字符：允许蒸馏。
- 80,000 至 150,000 字符：仅在确认是单一法规、规则或短章节时处理，否则跳过。
- 超过 150,000 字符：跳过并标记为 `skipped_too_large`。
- 明显属于整本教材、专著、手册或数百页文档的文件：跳过并标记为 `skipped_book`。
- 任何因 OCR、文件内容、API、schema 或预算导致的未处理项，都必须记录文件路径和具体原因。

### 候选卡审核与批准

蒸馏结果先写入 `candidate`。本轮不要求用户逐张手工批准，由执行流程自动审核合格卡片并执行 `kb approve`。审核至少检查：

- 卡片内容能否由来源 Markdown 支持；
- `scope`、flag 和 `evidence_required` 是否属于对应 scope 的允许范围；
- 触发条件、所需字段、例外和出处是否明确；
- 是否与已有卡片重复或冲突；
- 是否存在买卖指令、无依据推断、整段抄录或明显乱码。

审核不合格的卡片保留为 `candidate`，不得进入运行时检索，并在本文件记录卡片 ID 和不通过原因。合格卡片批准后，才允许被四个分析 Agent 的 `search_methodology` 检索。

### 预算与停止条件

- 本轮预算上限：10 元。
- 使用 DeepSeek，选择非高峰时段执行以降低费用。
- 逐文件记录 token 用量和费用估算。
- 达到预算上限或剩余预算不足以安全完成下一文件时，立即停止，并将剩余文件标记为 `skipped_budget`。

### 每文件最终状态

每个文件必须归入以下状态之一：

- `approved`：蒸馏成功、审核通过并已批准。
- `candidate_review_failed`：生成了 candidate，但审核不通过。
- `skipped_needs_ocr`：转换结果需要 OCR，本轮跳过。
- `skipped_too_large`：超过长度门槛。
- `skipped_difficult`：超过本轮容易处理的 80,000 字符门槛，或属于需要章节级拆分/复核的复杂资料。
- `skipped_book`：识别为整本书或大部头资料。
- `skipped_budget`：预算止损后未处理。
- `failed_api`：DeepSeek/API 调用失败。
- `failed_schema`：输出无法通过项目 schema 校验。
- `rejected`：candidate 经过去重/来源/质量复核后明确拒绝，不会被运行时检索。

本轮结束后，本文件补充四个 scope 的汇总、批准卡片清单、未批准卡片清单、跳过清单、失败清单、token/费用统计，以及明确的未覆盖范围。
