# 轻量股票看板平台方案

> 状态：**待审，未实现**  
> 日期：2026-08-24  
> 位置：本仓库 `doc/`  
> 配套：InsightAgent 首次研究 / 跟踪；本文只做 **延迟行情看板 + 数据底座**，不做实时交易、不做荐股。  
> 口径：研究辅助展示，**非投资建议**。

---

## 0. 结论（先看这段）

可以做，而且应该和 Agent **拆开**：看板是「全市场、延迟、可检索的数据面」；Agent 是「对一只票做四维研究」。两边共用 AKShare 适配思想，**不要**让 Agent 每次 `analyze` 都去打东财个股接口——改为读看板已经落好的库。

**半小时抓一次：同意，作为行情层的上限频率。** 用来规避高频、实时、逐笔。但「拿到所有股票数据」不能理解成：每 30 分钟对 5000 只票各跑一遍现在的 `fetch_fundamental` / K 线 / 公告。那样仍会被封，也没必要。

拆成三层：

| 层 | 覆盖 | 频率 | 取数方式 |
|---|---|---|---|
| A 全市场行情 | 全部 A 股最新价、涨跌幅、成交额等 | **30 分钟** | **一次（或少数几次）批量接口** |
| B 证券主数据 | 代码、名称、行业、上市状态 | **每日** | 批量代码表 |
| C 个股深数据 | 财务、估值分位、公告、日 K | **每日或打开详情/发起研究时** | 按票、限速、队列 |

看板读 A+B 就能列全市场；点进一只或点「研究」才动 C。Agent 的 snapshot 优先从 C/A 读，AKShare 当补洞，不当前端请求的同步依赖。

前后端分离：浏览器不碰 AKShare。只有一台 **采集 worker** 出网；API 只读本地库。

## 1. 产品范围

### 1.1 做

- 全 A 股列表：代码、简称、行业、最新价、涨跌幅、成交额、更新时间（延迟，标注「截至 xx:xx」）
- 搜索 / 按行业、涨跌幅筛选；自选股（本地用户）
- 个股页：延迟行情 + 最近日 K（够画图即可）+ 最近公告标题列表
- 数据新鲜度、上次采集成功/失败、覆盖股票数（运维条）
- 预留：从个股页跳转 `analyze {code}`（CLI 或以后再包一层研究 API）

### 1.2 不做（本期）

- 实时推送、Level2、盘口、模拟交易、下单
- 全市场每 30 分钟重算四维 Agent 报告
- 用户账号体系 / 多租户（先单机 `local`）
- 把 Streamlit 当正式前端（设计文档里的 Streamlit 仅 Agent 调试，看板用独立 SPA）
- 采集进程与 API 进程抢同一把 AKShare 连接狂打

## 2. 为什么半小时可以，但必须批量

A 股约 5000+ 只。现有 Agent 适配是 **按代码** 调 `stock_individual_info_em`、历史 K、公告等。5000 × 每接口 1～2 秒 × 多个接口，一轮要小时级，半小时窗口打不完，也容易触发源站限制。

半小时的价值是：**降低请求频率、接受延迟、固定节拍**，不是「全深度字段都 30 分钟一刷」。

行情层应使用东财/新浪类 **全市场快照**（AKShare 中一类 `stock_zh_a_spot*` 接口，实现时以当时可用函数名为准，封装在适配层）。一轮 = 有限次 HTTP，结果拆成 5000 行写入。失败则保留上一轮快照，看板显示 `stale=true`。

财务、公告变化慢：日更或「自选 + 最近打开」优先队列。与 30 分钟行情错开，避开整点洪峰（见 §6）。

## 3. 总体架构（前后端分离）

```text
浏览器 SPA                          本机 / 单实例
┌─────────────────┐                 ┌──────────────────────────────┐
│ Vue3 + Vite     │  HTTPS/JSON     │  API（FastAPI）               │
│ 列表 / 详情 /    │ ◄────────────► │  只读 SQLite/Postgres         │
│ 自选 / 新鲜度    │                 │  不调用 AKShare               │
└─────────────────┘                 └──────────────▲───────────────┘
                                                   │ 同库
                                    ┌──────────────┴───────────────┐
                                    │  Collector worker（独立进程）  │
                                    │  APScheduler 30min + 日任务   │
                                    │  只这里调 AKShare             │
                                    │  限速 / 熔断 / 审计           │
                                    └──────────────┬───────────────┘
                                                   ▼
                                              AKShare / 源站
```

Agent（现有 `python -m insightagent analyze`）后续加一个 `BoardMarketAdapter`：有板数据用板，没有再 fallback 现网。**本期方案可以先不改 Agent**，只把板独立跑通。

进程建议至少两个：`insightboard-api`、`insightboard-collector`。采集挂了，看板仍展示上一轮数据。

## 4. 技术选型

| 层 | 选择 | 原因 |
|---|---|---|
| API | Python FastAPI | 与 Agent 同语言，复用 `normalize_stock_code`、映射表 |
| 采集 | 同仓库包 `insightboard` 或 `insightagent.board`，独立入口 | 不要把调度写进 FastAPI 的 `startup`（重启 API 会打乱节拍） |
| 前端 | Vue 3 + Vite + 现成表格（如 Element Plus 或 Naive UI） | 看板以表格+搜索为主，不必上重型中后台 |
| 库 | **第一期 SQLite WAL**（`data/board.db`，与 `insightagent.db` 分开） | 单机轻量；行情只留「最新一轮全市场 + 日 K 滚动窗口」 |
| 缓存 | API 进程内存缓存 30～60 秒热列表 | 避免前端轮询打爆 SQLite |
| 鉴权 | 本期无；仅监听 `127.0.0.1` | 公网暴露再加 |

若日 K 要留年级别全市场，SQLite 会胀。那时再迁 PostgreSQL，API 合同不变。

前端轮询：列表页 **60 秒**拉一次 `/quotes`（数据本身 30 分钟才变，轮询只为看到采集完成）。不要 WebSocket。

## 5. 数据模型（逻辑）

全部 `as_of` 用采集完成时刻的 UTC；展示转东八区。空值用 `null` JSON，不造 0。

**universe（日更）**  
`stock_code` PK，`name`，`industry`，`market`（sh/sz/bj），`status`（listed/delisted），`updated_at`

**quote_snapshot（30 分钟，只保留当前轮 + 可选上一轮）**  
`stock_code`，`price`，`change_pct`，`open/high/low`，`volume`，`turnover`，`pe`/`pb`（接口有则写，没有 `null`），`batch_id`，`as_of`，`source`

一轮一个 `batch_id`。写入策略：先写 staging 表，校验行数（例如 ≥ 上市 A 股的 90%）再原子切到 current。失败不切，避免半截表。

**bar_daily（日更或随行情附带）**  
`stock_code + trade_date` PK，OHLCV。每票保留最近 250 个交易日够技术图；更早的可删。

**notice_headline（个股深数据，低频）**  
标题、日期、源、`stock_code`。全文不进库（与 Agent「大文本外置」一致）；看板只列表。

**ingest_run（采集审计）**  
`run_id`，`layer`（quotes/universe/deep），`started_at`，`finished_at`，`status`，`row_count`，`error`，`source`

前端顶栏只读最近一次成功 quotes 的 `as_of` 和 `stale`（超过 45 分钟无成功则黄条）。

自选：`watchlist(user_id, stock_code)`，`user_id` 先写死 `local`。

## 6. 采集节拍与风控

### 6.1 时间表（东八区）

- **行情 A**：每 30 分钟；**交易时段**（约 9:15–15:15，含盘前集合）跑；夜盘无 A 股则跳过或一天收盘后再跑 1 次打卡。
- **主数据 B**：每个交易日 8:30 一次（开盘前）。
- **深数据 C**：每个交易日 16:30 后，**只处理自选 + 当日被打开详情的票 + 最近 7 天 Agent 研究过的票**；全市场财务不要跟 30 分钟行情抢。全市场财务若要做，单独「周末全量」任务，QPS 极低。

非交易日：行情任务跳过；主数据仍可周日对齐退市。

### 6.2 限速

- 批量接口：两次调用间隔 ≥ 3～5 秒；失败指数退避，单接口一轮最多 3 次。
- 个股深数据：全局令牌桶，例如 **1 票 / 2～3 秒**，单日上限（如 300 票），超出留到次日。
- 熔断：连续 3 轮行情失败 → 停止 2 小时，看板 `stale`，人工可 `collector resume`。
- User-Agent / 调用方式走 AKShare 默认，**禁止**前端、禁止多机同时采同一源。
- 采集日志不落 HTML 原文。

「规避风险」主要靠：**批量、低频、熔断、深数据按需**，而不是只改成 30 分钟仍按只打。

### 6.3 与 Agent 隔离

`INSIGHTAGENT_DB` 与 `INSIGHTBOARD_DB` 两个文件。采集写 board；Agent 写 research。以后 Agent 只 **读** board 的 quote/bar，不在研究请求里同步 AKShare 全套（可另开任务）。

## 7. API（后端给前端）

前缀 `/api/v1`，JSON，字段稳定，错误 `{ "error": "...", "code": "..." }`。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/meta/health` | API 活着；不表示采集活着 |
| GET | `/meta/ingest` | 最近行情/主数据/深数据任务状态、`quotes_as_of`、`stale`、`stock_count` |
| GET | `/universe` | 代码表；`?q=` 前缀搜索，limit 50 |
| GET | `/quotes` | 当前全表分页：`cursor` 或 `page&size`（size≤100）；`sort=change_pct`；`industry=` |
| GET | `/quotes/{code}` | 单票最新行情 |
| GET | `/bars/{code}` | `?limit=120` 日 K |
| GET | `/notices/{code}` | 标题列表，可空 |
| GET | `/watchlist` | 自选 |
| PUT | `/watchlist/{code}` | 加入 |
| DELETE | `/watchlist/{code}` | 删除 |

不做：前端传任意 AKShare 函数名；不做 SQL 透传。

分页必须有。5000 行一次丢给浏览器会卡，列表默认按成交额或涨跌幅取前 100，搜索走 `universe`+`quotes` 过滤。

CORS：仅配置的前端 origin（开发 `localhost:5173`）。

## 8. 前端页面

1. **市场**：指数（若本期指数接口不稳定可先不做指数，用全市场涨跌家数统计代替：上涨/下跌/平家，来自当前 `quote_snapshot`）。  
2. **行情表**：搜索框、行业、涨跌幅区间；列：代码、名称、最新价、涨跌%、成交额、`as_of`。  
3. **个股**：行情数字 + 简易 K 线（ECharts）+ 公告标题；按钮「加入自选」。预留「发起研究」灰按钮。  
4. **自选**：只显示 watchlist ∩ quotes。  
5. **底栏/顶栏**：数据截至时间；stale 黄条。免责声明固定可见。

交互：个股页进入时若 C 层没有公告/K 线，**不要**让浏览器触发采集。显示「日更未覆盖」；由 worker 队列慢慢补（打开详情可把该 code **写入优先队列表**，worker 下一分钟限速拉取）。这样「看起来像点开就有数」，实际仍是异步、限速。

## 10. 分期

| 期 | 交付 |
|---|---|
| B0 | 采集：批量行情 30 分钟 + universe 日更；API：health/ingest/quotes 分页；前端：表 + 搜索 + 新鲜度。单机 SQLite |
| B1 | 日 K、个股页、自选、打开详情入队深数据（公告标题） |

| B3 | 指数、行业统计、watchlist 与 Agent 关注列表对齐 |

B0 就能验证「半小时 + 全市场列表」是否稳；不要 B0 就上财务全量。

## 11. 风险与验收

| 风险 | 对策 | 验收 |
|---|---|---|
| 源站限流 | 批量、熔断、深数据限速 | 连续 5 个交易日行情任务成功率 ≥ 80%，失败不空洞表 |
| 「全数据」期望 | 文档写死三层 | 产品说明：列表=全市场延迟行情，不是全套研报字段 |
| API 误去爬 | worker 独占 | 压测 `/quotes` 时无 AKShare 流量 |
| 库膨胀 | 行情只留当前轮；K 线 250 日 | 三个月体积可预期 |
| 当成实时 | UI 写「延迟，约 30 分钟」 | 无 WebSocket、无秒级刷新承诺 |
| 口径错误（上次 000858 ROE） | 看板行情用快照原字段；财务进 C 层后与金融侧对口径 | B1 前不展示未校验的财务结论 |

## 12. 和你提的原话怎么对齐

- **要能拿到所有股票数据**：B0 指 **全部上市 A 股的延迟行情 + 代码主数据**。财务/公告不是每 30 分钟全市场。  
- **不需要实时**：对，按 30 分钟批次，UI 标明截至时间。  
- **半小时抓一次规避风险**：作为行情层上限，且必须是 **批量接口**；再叠加交易时段过滤、熔断、深数据按需。  
- **前后端分离**：Vue SPA ↔ FastAPI；采集第三进程。  

若同意 B0 范围，下一步才是接口名调研（冻结用哪一个 `spot` 函数）和建 `insightboard` 包。未审前不写业务代码。
