## 一、跨用户记忆隔离（安全，最重要）

### 1.1 问题

研究档案编号只由股票代码生成（`000858-initial`），检索专家记忆时只按「专家 + 档案 + 是否成功」过滤，**用户身份完全不参与**。用户 A 在某只股票上写下的私有记忆（来自 A 的口头要求与偏好），会被用户 B 分析同一只股票时原样继承。

已实测复现：A 写入后，B 能查到 A 的完整记忆。

### 1.2 改了什么

| 文件 | 改动 |
| --- | --- |
| `contracts.py` | 状态模型增加 `user_id` 字段 |
| `business_contracts.py` | 运行记录增加 `user_id` 字段 |
| `persistence.py` | 新增迁移 5：`agent_states`、`sessions` 增加 `user_id` 列 + 索引；插入/更新都写入该列；记忆检索增加用户过滤；继承父会话时校验用户一致 |
| `state.py` | 内存实现同步：按用户过滤、继承时校验角色/档案/用户 |
| `runtime.py` | `AgentInstance.run` 接受 `user_id`，落入状态 |
| `initial_research.py` / `tracking_agent.py` | 创建运行记录时写入用户；四个专家与追踪代理由 `run.user_id` 统一传入 |

### 1.3 兼容性

历史数据的 `user_id` 为空，检索时按空串匹配，**不会被任何新用户读到**。这是刻意的：宁可让旧记忆"失联"，也不能串号。

### 1.4 验证

```
alice 写入记忆 → bob 查询：None
alice 自己查询：完整记忆
bob 强行指定 alice 的会话编号作为父会话：继承到 {}（空）
```

## 二、失败路径（流程不再卡死）

### 2.1 首次研究：run 卡在"进行中"

**原因**：运行记录先落库，但失败保护直到取数阶段才开始。中间的"解析意图、读取偏好"一旦出错，异常直接穿出函数，没人把状态改成失败。后果是这条股票的后续反馈与追踪**永久被锁**（后续操作要求父记录为成功/降级）。

**改法**：失败保护的起点提前到写库之后立刻开始。
**附带修掉**：`macro_fetch_error` 原本在 try 内部初始化，失败处理会读到未定义变量并掩盖真实错误，现提前到 try 之外。

### 2.2 反馈：子 run 卡在"进行中"

同上，子运行记录先创建，提交意图在保护之外。现单独包一层，失败时写 `run_failed` 审计再抛出。

### 2.3 被取消的会话永久 `RUNNING`

**原因**：只捕获普通异常，捕获不到"任务被取消"（超时正是靠取消实现）。**改法**：改为捕获 `BaseException`，取消也标记失败。

### 2.4 失败标记掩盖原始错误

记录失败时若再次出错，新异常会顶替原异常，上游的异常分类失效。**改法**：失败标记改为尽力而为，永不抛出。

### 2.5 排队任务永不过期 + worker 一崩就死

- 排队超过阈值（4 倍执行阈值）的任务标记失败，不再让该标的永久返回 409。
- worker 主循环整体包异常保护，单次迭代失败时打印并继续，不会整个线程退出。

## 三、数据正确性

### 3.1 0 元价格成交

行情批次发布校验只检查"价格非空"，不检查"大于 0"。盘前数据源确实返回 0，于是 0 元成交、不扣现金、成本记 0、持仓凭空出现。

**改法**：发布校验与下单校验都要求价格 > 0。

### 3.2 证据校验漏掉列表字段

报告里的数字必须能在快照中逐字命中，但收集"允许的数字"时只收集标量，把 `roe_series` 这类列表整段跳过。模型照抄快照里真实存在的 ROE 序列，仍被判为幻觉 → 重跑整维 → 弃权。

**改法**：递归收集所有嵌套数值（标量、列表、字典）。

### 3.3 搜索通配符未转义

股票搜索把用户输入直接拼进模糊匹配，输入 `%` 会命中全市场。**改法**：转义 `%`、`_`、`\` 并显式声明转义符。

### 3.4 证据重试继承被否决的记忆

绑定失败后重试会新建会话，但**失败那次的会话状态仍是成功**，于是：
- 重试会把它当作父会话，继承其中"没绑上的数字"；
- 未来所有 run 也可能继承这段坏记忆。

**改法**：绑定失败时把该会话标记为失败（并记录 `rejected_by=evidence_binding`），检索自动跳过它。

### 3.5 画像把"无行情"算成"盈利"

持仓的浮动盈亏在拿不到行情时为 0，统计"盈利持仓占比"时 `0 >= 0` 成立，于是整组持仓都被算成盈利，喂给画像模型后编出"止损纪律好"之类的结论。

**改法**：改为三态（是/否/未知），并附"行情是否可用"标记，模型可据此降低置信度。

## 四、上下文与模型交互

### 4.1 "关键消息不许压缩"机制从未生效

压缩逻辑里有"打了保留标记就不删"的分支，但**全仓没有任何地方设置这个标记**，所以保护从未触发过。任务定义（目标、必填问题、约束、跨轮记忆）只要滑出最近若干条就被删掉。

**改法**：
- 任务输入打保留标记；
- 快照类工具结果（基本面/技术/情绪/宏观/价格/K线/股东/追踪上下文）打保留标记；
- 保留判断不再与"优先级 ≥ 90"耦合（原来那个条件让标记几乎永远不生效）。

### 4.2 压缩预算与输出上限矛盾

压缩模块固定预留 4096 token 输出，而专家实际允许输出 32768。第一版改成"预留 = 实际上限"后直接算成负预算、所有请求都溢出（被测试当场抓住），最终改为：**预留量取实际允许输出，但不超过窗口的一半**。

### 4.3 中文 token 低估 3-4 倍

原来的估算公式 `(字符数+3)/4` 是英文经验值。项目内容几乎全是中文（约 1 字 1 token），导致判定"装得下"而实际超限，请求被拒后整轮失败。

**改法**：按字符类别加权——中日韩字符每字 1 token，其余每 4 字符 1 token。同时不再把"推理内容"计入请求预算（见 4.4，该内容已不发送）。

### 4.4 模型推理内容被回传

持久化层特意剥离了模型的内部推理（并写明原因），但内存中的消息缓存没有剥离，于是它被原样塞回请求发给模型。轻则白烧 token，重则接口直接拒绝。

**改法**：序列化时永不输出推理内容；对应测试的旧断言（"推理内容必须被返回"）同步改为断言"不得出现"。

### 4.5 模型调用无超时

SDK 默认 600 秒超时 + 2 次重试，比研究 worker 自己的 8 分钟预算还大，注定被超时放弃并留下孤儿任务。

**改法**：显式 90 秒超时、最多重试 1 次。

### 4.6 专家子 Agent 被重试 4 遍

专家调用没有指定重试策略，走默认（重试 3 次），而它执行的是"一整个子 Agent 循环"。超时后会把整个子 Agent 重跑，最坏 4 遍，且最终异常不在工具层的捕获列表里，直接炸掉整轮追踪。

**改法**：子 Agent 重试次数设为 0（失败即上报）；超时从 180 秒放宽到 480 秒。

## 五、意图解析

### 5.1 显式标签被自然语言越权

`#rerun #fundamental 技术面那段挺好别动` 这条命令，显式标签只点了基本面，但正文里出现的"技术面"仍被并进重跑清单。

**改法**：自然语言推断出的维度只在"完全没有显式标签"时参与；模型抽取出的维度仍然保留（那是忠实抽取）。

### 5.2 否定盲

"这次不用再看一遍了"、"别重跑，我只是记一下"这类句子包含重跑短词，仍会触发重跑。

**改法**：标记匹配增加否定窗口——紧跟"不用/不要/别/无需/不必/先不/不想"的命中不算。

### 5.3 垃圾词绕过记忆门

记忆门的作用是"只把可执行的短规则存成偏好"。但它先判断"是否命中检查词"，命中就跳过垃圾词过滤。于是"写得不行，估值太差"因为包含"估值"被存成永久纪律，之后每次分析都注入专家。

**改法**：垃圾词无条件否决，不再被检查词白名单绕过。

### 5.4 "结束"语义不清槽

用户说"算了/不用了"时，只把正文置空，**抽取到的槽位仍被当作约束塞给专家**。

**改法**：结束语义下清空全部槽位。

### 5.5 长问句被截成约束

先截断到 200 字再判断是否问句，导致长问句的"？"被截掉、降级成约束；截断点还可能落在否定词之后，把语义反转。

**改法**：在原串上判断问句；截断优先落在句读边界（。；，）并追加省略号。

### 5.6 不带重跑标记的反馈无人消费

反馈的默认语义是"这次不重跑，留给下一次"。程序确实把它写进库并打了"留给下一次"的标记，但**全仓只有写入、没有读取**——下次分析完全不看它，而命令行还会回显"意图理解……"。

**改法**：分析开始时读取上一次成功 run 的挂起意图并合并进本轮（与追踪链路已有的做法对齐），同时记一条审计。只读取最近一次成功 run，因此一条反馈被消费后不会无限叠加。

## 六、看板前端状态机

前端改动集中在 `src/insightboard/web/app.js`（+131/-约 20 行）。

| 问题 | 现象 | 改法 |
| --- | --- | --- |
| 换股时一个请求 404 | 界面已切到新股票，内容仍是旧股票，此时点分析会对着**新**股票下单 | 行情/日线/公告三个请求各自降级；行情缺失时显示"不在最新行情批次" |
| 失败任务污染"当前任务" | 之后每次反馈都返回 409，必须退出重进页面 | 失败分支回滚到最近一次成功任务，并摘掉"分析中"徽章 |
| 轮询被一次网络抖动打死 | 后端成功了，前端永远显示"分析中" | 指数退避重试最多 3 次，再失败给出明确提示 |
| 跨标的轮询污染 | A 股票的结果渲染进正在查看的 B 股票页面 | 轮询与日线拉取都捕获发起时的标的，每轮校验不一致即终止 |
| 采集按钮永久变灰 | 状态查询失败后轮询链断掉 | 轮询加异常处理与重试上限；另加 30 秒一次的后端状态自愈 |
| 账户接口失败锁死按钮 | 解锁依赖的请求失败后被静默吞掉，追踪/反馈/下单全部变灰 | 失败也推进状态机；请求在途时禁用开始按钮 |
| 看历史版本污染反馈基线 | 反馈悄悄基于三天前的旧版本分叉，覆盖最新结论 | 查看历史不再改写"当前任务/结果"编号，并提示"仅查看" |

验证：`node --check` 通过。前端仍无自动化测试，建议后续手工过一遍四条路径（换股、分析、追踪、反馈）。

## 七、知识库卡片（7 张，候选状态）

全部写了 JSON 到 `doc/kb-entries/`，导入了 `data/kb.db`，但状态是 **candidate**——按"卡片批准权留给人"的设计，**未审批不生效**。

| 卡片 | 作用 |
| --- | --- |
| 基本面兜底卡 | 数据正常、没触发任何特征时的基础四问 |
| 技术面兜底卡 | 无形态时的趋势与位置检查 |
| 事件兜底卡 | 无重大事件时的信息真空处理 |
| MACD 信号卡 | 填补唯一完全空白的标签（依据《技术面规则》的 Appel 2005 口径） |
| 估值中性卡 | 估值不高不低这一档此前缺失 |
| 数据不足纪律卡 | 数据不全时如何诚实处理 |
| 弃权折扣规则卡 | 把代码里硬编码的置信度规则固化成可审批的卡片 |

配套的契约改动：允许"只靠排除条件限定"的卡片、允许标记"永远适用"的兜底卡。
