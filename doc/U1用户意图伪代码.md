# U1 用户意图

> 范围：仅 U1。不实现 rerun / 画像 / 宏观 Agent / session 复用。  
> 不存用户原话。六槽必填 string，空为 `"none"`。  
> 下文先讲方案和想法，再附伪代码对照现有文件。

---

## 方案（要做成什么）

今天用户只能丢一个股票代码。三个专家的 user 消息是同一句死指令，所以「用户怎么用这套系统」进不了作业。

U1 只补这一截：

```text
用户可选输入一段话 + 可选 tag
    → 程序认 tag、剥掉 tag
    → LLM 把剩余正文拆成六槽（基本面/技术面/情绪/宏观/决策/追踪）
    → 有内容的槽写进对应专家（或决策）的 Task
    → 若带 #remember，把槽里的短句存成偏好，下次同维自动带上
```

没有主 Agent。首次研究仍是 `analyze_stock` 这条 workflow：它负责拆 intent，然后分发给已经在跑的三个 `AgentInstance`。专家 System 不动；Evidence 仍是 snapshot 工具；**用户口径只出现在 user JSON 的 questions/constraints**。

空输入必须和现在完全一样：不调抽取模型，三专家 instruction 字面不变。这是能上线的底线。

---

## 想法（为什么这样拆）

**1. 拆槽是编排的事，不是专家的事。**  
让基本面自己读用户全文，它会看见技术面的话，也会把闲聊当指令。所以抽一次 `UserIntent`，每维只收属于自己的一句。宏观 Agent 还没有：宏观槽可以记偏好，但 U1 不 run 宏观。

**2. 原话不是记忆。**  
库里只放抽取后的短句（preference）和一次事件（用了哪些 tag、什么 effect、对着哪次 run）。不归档原文，避免检索时把聊天当规则。

**3. tag 是程序字段，不是模型猜的。**  
`#fundamental` `#remember` 由正则 + 死词表识别。模型只填六个维槽和 `not_evidence`。无 tag 合法：全靠 LLM 从正文填槽，填不出就 `"none"`。

**4. 有 tag 但 LLM 仍 none，U1 不把正文塞进槽。**  
否则原文会进 Task、甚至进 preference，等于绕过「不存原话」。tag 在 U1 主要用于 `#remember` 的效力，以及你事后看 utterance 知道用户点过哪一维。句子来源只有抽取。

**5. `#rerun` 这期只记账。**  
重跑要复用 session、追加 Decision，会搅进另一条线。U1 把 effect 写下即可，调度以后再做。

**6. 决策槽不进四个专家。**  
`intent.decision` 只拼进 `build_multi_factor_decision` 的 rationale 前缀，不改评级规则、不改缺维、不当 citations。

**7. 偏好按维检索，最多 8 条。**  
防止 Task 被历史口径淹没。`#decision` 的偏好只给决策函数，不渗基本面。

**8. 抽取失败不当成产品失败。**  
JSON 坏了就六槽全 none，分析照跑，audit 记 `intent_schema_invalid`。只有缺字段/null 这种 schema 损坏算抽取失败；全 none 是合法空意图。

## 怎么写（对着仓库动手）

按依赖写，先能单测抽取，再动 workflow。

**合同 `user_contracts.py`**  
三个模型：`UserUtterance`、`UserIntent`、`UserPreference`。全部 string，禁止 `Optional`。空用 `"none"`。`UserUtterance` 没有 raw。LLM 另用 `LlmIntentSlots` 七键，避免模型改 `effect`/`tags`。

**抽取 `user_intent.py`**  
`parse_tags` 纯函数，无 I/O。`extract_slots`：body 为 none 直接返回全 none；否则一次 `thinking_enabled=False` 的 JSON 调用，校验失败则全 none。不要在这里调专家。

**库 `user_store.py` + 迁移 v2**  
现有 `initialize` 只在 version&lt;1 时跑 MIGRATION_1，必须加 `version&lt;2` 跑新四表。表全 TEXT NOT NULL。`active_preferences(scope, stock_code)` 给 workflow 用。

**拼包**  
写 `build_expert_user_query`：在现有 `instruction` 上加 `objective/reason/required_questions/constraints`。槽是问句进 questions，否则进 constraints 并加前缀「用户口径：」。再 append 该维偏好。

**改三个 `_run_*_agent`**  
只加参数 `user_query: str`，删掉函数内部那份死 `json.dumps`。System、工具注册、parse_report 都不动。

**改 `analyze_stock`**  
增加 `user_prompt=NONE`。在已有 `run_id` 之后：剥 tag → 抽槽 → 存 utterance/intent → 或许 remember → 查出三维偏好 → gather 时把拼好的 user_query 传进去。严重缺字段的提前弃权分支也要能带上 `user_constraint`，因为 remember 可能已经写下。

**改 `build_multi_factor_decision`**  
加 `user_constraint: str = NONE`。非 none 时只改 rationale 字符串，评级逻辑不动。用现有决策测试：传 none 时 JSON 应与现在逐字可比。

**CLI**  
`--prompt` 默认 `"none"`。不要把 prompt 打进 audit 正文。

**测试**  
先测 parse/extract/拼包/remember 不出现原文。再跑现有三专家夹具：`--prompt none` 必须过。最后加一条 FakeLLM：先回 slots JSON，再回三个专家的既有响应。

坑：抽取和专家共用一个 FakeLLM 队列时，响应顺序会绑死；测 workflow 时要按「抽取 → 基本面 → 技术面 → 情绪」排队。偏好条目不要再套一层「用户口径：」。

## 1. parse_tags

```
function parse_tags(raw: str) -> (tags_json, effect, body, tagged_dims_json)
    if raw == "" or raw == NONE:
        return '["none"]', "this_run", NONE, '["none"]'

    found = []
    dims = []
    remember = false
    rerun = false
    rest = raw

    for each token matching /#[^\s#]+/ in raw:
        mapped = TAG_ALIASES[token] or TAG_ALIASES[lower(token)]
        if mapped is missing: continue          # 忽略未知 tag，不失败
        found.append(mapped)
        rest = rest.replace(token, " ", 1)
        if mapped == "remember": remember = true
        else if mapped == "rerun": rerun = true
        else if mapped in {fundamental,technical,sentiment,macro,decision,tracking}:
            dims.append(mapped)

    if remember and rerun: effect = "remember_rerun"
    else if remember: effect = "remember"
    else if rerun: effect = "rerun"
    else: effect = "this_run"

    body = strip(rest)
    if body == "": body = NONE
    tags_json = json(found or [NONE])
    tagged_dims_json = json(dims or [NONE])
    return tags_json, effect, body, tagged_dims_json
```

`body` 只留在内存，禁止 save。

## 2. 抽取

```
EXTRACT_SYSTEM = """... 只输出 7 键 JSON，值是短句或 none，禁止 null/缺键/空串/复述原文 ..."""

function empty_slots() -> dict
    return {
        fundamental, technical, sentiment, macro, decision, tracking, not_evidence
    } 全部 = NONE

async function extract_slots(llm, body, model) -> dict
    if body == NONE:
        return empty_slots()          # 不调 LLM

    req = LLMRequest(
        model=model,
        messages=[system EXTRACT_SYSTEM, user body],
        thinking_enabled=False,
        response_format="json",
        max_tokens=1024,
    )
    try:
        resp = await llm.complete(req)
        slots = LlmIntentSlots.parse(json.loads(resp.content))
        return slots
    except 任何 JSON/校验错误:
        return empty_slots()          # 不当用户失败；专家仍默认跑
```

程序字段（模型不许填）：`intent_id, utterance_id, effect, tags`。  
拼 `UserIntent = 程序字段 + slots`。校验失败 → 当 empty_slots，audit `intent_schema_invalid`（payload 无 body）。

**U1 不把 body 写入槽。** tag 只影响 `effect` 和 remember 的 scope 候选；句子只来自 LLM。

## 3. remember（无 rerun）

```
function persist_remember(store, intent, utterance, stock_code, run_id):
    if intent.effect not in {"remember", "remember_rerun"}:
        return
    for dim in [fundamental, technical, sentiment, macro, decision, tracking]:
        slot = intent[dim]
        if slot == NONE: continue

```

## 4. 拼专家 user_query（替换死 JSON）

```
DEFAULT_INSTRUCTION = {
    "fundamental": "Analyze this stock from the precomputed snapshot. Call get_fundamental_snapshot, then return the final JSON.",
    "technical":   "Analyze trend from precomputed indicators. Call get_indicator_snapshot, then return the final JSON.",
    "sentiment":   "Analyze material events from the event snapshot. Call get_event_snapshot, then return the final JSON.",
}

function split_slot(slot) -> (questions[], constraints[]):
    if slot == NONE: return [], []
    text = slot[:200]
    if text ends with "？" or "?": return [text], []
    return [], ["用户口径：" + text]

function build_expert_user_query(run, snapshot_or_code, as_of, dim, intent, pref_statements[]):
    q, c = split_slot(intent[dim])
    for s in pref_statements[:8]:
        c.append(s[:80])
    return json.dumps({
        "run_id": run.run_id,
        "stock_code": code,
        "as_of": as_of,
        "output_schema_version": "1",
        "instruction": DEFAULT_INSTRUCTION[dim],
        "objective": "完成本维分析",
        "reason": "首次研究",
        "required_questions": q,
        "constraints": c,
    }, ensure_ascii=False)
```

槽为 NONE 且无偏好时，`q=[] c=[]`，`instruction` 与今天字面相同。
