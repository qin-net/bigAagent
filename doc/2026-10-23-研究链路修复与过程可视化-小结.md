# 研究链路修复与过程可视化 · 小结

日期：2026-10-23
分支：`main`（本地领先 `origin/main` 1 个提交，待推送）

---

## 一句话

从一次「8 轮熔断」的报错查起，修掉了三类让错误原因失真的文案，把取数从 23 秒压到 11.5 秒，给研究过程做了一块能看着往前推的地图，并让「跑到一半进程挂了」这件事不再变成白屏或悄悄重跑。

---

## 一、起因：一次 8 轮熔断

点分析后 88 秒失败，`research_job.error` = `MaxLoopRoundExceeded: max_loop_round=8`。

用库里录的真实参数离线重放后定位到根因（**零模型调用**）：模型把 `state_patch.append` 写成了 `{}`，而该字段是数组。校验失败后，代码抛出的却是固定文案「`output.report is required and must include role, score, and stance`」——真实字段被吞掉了。模型信了这句话，五轮反复重写 `report`（内容一次比一次好），`append` 始终是 `{}`，8 轮用完后整次运行作废。

| 修复 | 位置 |
|---|---|
| `state_patch` 的 `set/append/remove` 接受 `null`/空对象 `{}`，归一成 `[]`（非空 dict 仍报错） | `runtime.py` `SubmitStatePatch` |
| 校验失败时把**真实字段路径**带给模型（`state_patch.append: Input should be a valid list`） | `runtime.py` `_describe_validation()` |
| `arguments` 不是合法 JSON 时不再甩锅给 `report`，改为报告 JSON 错误位置，尾部落点还提示"像是被截断" | `runtime.py` `_parse_tool_calls` |

重放验证：那次运行里 12 次真实提交，**10 次原本被误杀的现在直接通过**；剩下 1 次是真问题（`non-abstain report requires citations`），新文案让模型一轮就改对。

## 二、耗时：取数改成并发

`initial_research.py` 里四次网络取数原本是一个接一个 `await`，真实运行时**取数独占 23 秒**（49 秒总时长里接近一半）。

改法：基本面 / 情绪 / 宏观三路 `asyncio.gather` 并发；技术面走 board 本地 SQLite，留在原位串行。

| 指标 | 改造前 | 改造后 |
|---|---|---|
| 取数（`run_started → snapshot_ready`） | 23.0s | **11.5s** |
| 其中情绪 / 宏观 / 基本面 | — | 3.1s / 2.3s / **11.4s（长尾）** |
| 整次分析 | 49s | **41s** |

**踩到的坑**：第一版直接在每个并发协程里写审计事件，结果 `analyze 999999 --fixture` 从 `degraded` 变成 `failed`，报 `sqlite3.OperationalError: attempt to write a readonly database`。原因是 `audit.append()` 走 `asyncio.to_thread`，每次开独立连接，两三个同时写就炸。修法：函数内一把 `asyncio.Lock`，所有并发分支的审计写入统一走 `_emit_audit()`。

## 三、过程可视化：从"阶段目录"到"推进地图"

第一版做成了 6 行固定阶段名 + 一个闪的圆点，被判定不合格——那是目录，不是过程；而且把 1 秒就过去的"准备研究"摆在显眼处，却把"谁交了卷、说了什么"折叠起来。

现有版本：

- **路线**：取数 → 四维分析 → 汇总结论，进度条按真实比例填充，队伍标记用双圈呼吸动画跟着走
- **四条泳道**：四个专家各自一张卡，显示状态、**自己的耗时**、已交卷后的 stance/score 与**两行摘要**（标注"单维摘要，综合结论尚未生成"）
- **秒表由前端自己走**：服务端只给基准秒数，前端 `setInterval(100ms)` 累加，轮询只负责纠偏与更新状态——否则每 2.5 秒才跳一次，看着一卡一卡
- **重建节流**：`progressSignature()` 不变时只纠偏、不重建，避免动效和展开状态被打断
- **收尾**：结论到位时 150ms 淡入替换

数据来源是 append-only 的 `audit_events`（新增 `fetch_started` / `fetch_completed` 每维事件，`agent_completed` 改为**每维完成即发**并带 200 字摘要）。**没有新增任何可变 progress 字段**，所以历史 run 也能回放进度。

## 四、中断任务的兜底

现象：研究没跑完、进程重启，再进页面**完全看不到进度**。

三层根因：

1. 进程内 worker 线程随服务重启而死 → `research_job` 永远停在 `running`，心跳（`updated_at`）停止
2. `recover_research()` 的老策略是"心跳超 8 分钟 → 置回 `queued`"→ worker 取走**从头再跑一遍**（再花一次钱，前几维结果不复用）
3. 页面进标的只调 `/stocks/{code}/current`（只返回成功的 run），失败/进行中的现场**没有任何入口**

修法：

| 项 | 做法 |
|---|---|
| 不再悄悄重跑 | `recover_research` 超时直接标 `failed`，error 写明"执行器中断"，要不要重跑由用户决定 |
| 重进能看到现场 | 新增 `GET /api/v1/research/stocks/{code}/latest-job`，返回任意状态的 job + 进度；前端进标的时先查它，running 就接着轮询，failed 就渲染红色中断态 |
| 孤儿任务的轨迹 | 未完成的任务 `run_id` 是空的，新增 `_guess_run_id()` 按「同标的 + 创建后 30 分钟窗口」找回审计轨迹 |
| 失败态不能继续涨秒 | 已结束任务的时长用最后一条事件时间截断，泳道显示「中断」并停表 |

顺带清了当时那个卡死的 job（心跳已停 201 秒、距自动重跑只剩约 2 分钟），把 `research_job`、`runs`、卡住的 `sessions` 一并标为失败。

## 五、关掉 initial_synthesis

队友上午落地的「首次分析综合叙事」在这台机器上跑不通：analyze 路径带 `thinking_enabled=True`，而合成用的 `max_tokens=8192` 是**思考与叙事共用**的预算。读 1.45 万字符报告后必截断，审计里是 `synthesis_failed / OutputTruncatedError`，单这一步跑了 **132 秒**且零产出。

处理：两个调用点传 `synthesis_llm_adapter=None`（该开关是 opt-in 且不回落，传 None 即整步跳过）。**没有改队友的 `tracking_agent.py`**，随时可以打开。

> **合并后记（fe9b68a 合入时）**：截断根因已在 `fe9b68a` 修掉——合成调用固定 `thinking_enabled=False`（推理外化到输出的 thinking 字段，不再与叙事抢预算），且 `tracking_synthesis_config` 的 max_tokens 提到 32768（与四个专家对齐）。修复先于本次关闭合入本地、真实链路三轮验证通过（见《首次分析综合叙事-initial-synthesis说明-20261023.md》实测章节），因此合并时已把两个调用点改回 `synthesis_llm_adapter=llm`，本节的临时关闭不再生效。若线上再见 `synthesis_failed`，按该文档的风险清单排查，而不是再次关闭。

## 七、已知局限与待办

1. **工具级动态尚未做**：现在最细粒度到"某维开始/结束"，看不到"正在调 search_methodology"。要做需在 `runtime.py` 的工具分发处加审计事件——那是队友的文件，且写进每次工具调用。
2. **反馈的分诊逻辑没动**（原计划预留）：现在靠关键词 + 维度点名决定重跑范围，「宏观确定吗」这类会被判成 `this_run` 而不重跑。改进方案见 `doc/mine/需求-研究过程可视化.md` 之外的讨论记录。
3. **`_guess_run_id` 是启发式的**：同一标的若在 30 分钟窗口内多次启动，可能匹配到第一条。只影响展示，不影响落库数据。根治办法是让 `execute_job` 在开跑时就把 `run_id` 写回 job 行。
4. **失败态的签名边界**：`progressSignature` 不含 error 文本，连续两次失败在**同一阶段**时，红条里的错误文案不会刷新。
5. **并发取数只做了保守版**：技术面仍串行。实测它 0.0 秒（board 日线已在库），四路并发的收益可以忽略。
6. **`initial_research.py` 是队友也在改的文件**，本次改动集中在取数段与四维包装两处，下次合并前需先 `git fetch` 比对。
